# MDM 与 Identity 独立前端

`apps/mdm` 是 Windows/macOS 企业终端管理入口，`apps/identity` 是 Identity 宿主认证入口。两者独立装配、构建和部署，不共享跨域会话。`@rss/auth` 导出既有 cookie 会话、认证 UI、OIDC flow 与路由；每个应用只创建一个 controller。`@rss/core` 持有展示基础，`@rss/api` 持有唯一 HTTP executor。原 apps/web 已由 #2514 退出，不恢复旧 bearer 页面。

## 开发

```sh
pnpm install --frozen-lockfile
pnpm dev:mdm:demo
```

打开命令输出的 loopback 地址，使用纯合成账户 `demo / demo`。顶部始终显示 Mock，可按设备、策略、软件、安全、运营模块显式选择来源和场景，或重置并重新登录。场景包括 normal/empty/denied/forbidden/offline/unsupported/partial/conflict/unknown/late；各业务包负责其具体数据及操作分支。演示状态仅在当前开发服务内存中，重启丢弃。多标签页共用该演示状态，不代表生产会话隔离。策略与软件共享 Resource、Scope 和执行边界，切换任一模块来源会同步切换另一模块。real 来源未接入的能力返回不可用，不切回 mock。

演示使用 Vite 本地 HTTP middleware，不能构建为生产静态站点；`--mode demo` 的 build 显式拒绝。它不运行 MDM/Identity 后端，不证明设备注册、擦除、脚本效果或合规。普通 `pnpm dev:mdm` 不提供模拟 API；真实交互应使用 HTTPS 同源产品宿主。Identity 开发继续见[宿主认证 UI](20260917-2368-embedded-identity.md#交互开发)。

## 生产构建与镜像

```sh
pnpm build:identity
pnpm build:mdm
pnpm image:identity --tag rss-identity-web:VERSION
pnpm image:mdm --tag rss-mdm-web:VERSION
```

`pnpm build` 构建并扫描两个生产目录。Identity 产物不包含 MDM 路由，MDM 不包含 demo server、模拟身份或场景控制。镜像只复制对应应用的 dist，使用独立版本标签。构建使用当前工作树，允许未提交修改。类型/组件/API 验证采用现有 `pnpm typecheck/lint/format:check/test:coverage/test:boundary`，不需要源码快照、提交摘要或 consumer receipt。

两个应用分别拥有独立域名上的 `/`；不能在同一根路径同时部署两个 app。Nginx 配置与 TLS 材料由宿主注入 `/run/config`，前端镜像不持有秘密。

MDM 宿主需提供既有 Identity config/context 和嵌入 Identity HTTP V1，以及新增的静态 `/api/v1/mdm-host/config.json`：

```json
{"canonicalOrigin":"https://mdm.example.test","tenant":"11111111-1111-4111-8111-111111111111"}
```

origin 必须严格匹配 HTTPS 页面 origin，tenant 是宿主指定资源定位符；不生成租户 header，也不授予权限。示例 [`deploy/mdm/gateway.conf.example`](../../deploy/mdm/gateway.conf.example) 精确区分 config、Identity callback、业务 API 和 SPA。这是前端接入要求；rss-mdm 宿主新增配置、路由和实际生产部署仍待后端 owner 接入，不宣称已交付。

升级时记录两个现用前端镜像标签/ID，分别构建目标产品镜像，保留宿主配置、TLS 和后端数据卷，仅替换对应 gateway 镜像；验证 `/`、后端 `/livez`/`/readyz`、登录/退出、受控工作区与 API 错误；readiness 未通过不切流。失败时将该 gateway 恢复到先前镜像并重建容器，不回滚 Identity/MDM 数据库、不重放未知写操作。两个前端可以独立升级回滚；若后端合同发生破坏性变化，先按后端部署说明协调版本，不靠旧 wire fallback。

MDM 管理 HTTP 统一使用 `/api/v1/{资源}`，保留每个资源的当前语义与权限；旧管理版本入口退出，部署不进行路径重写。Identity transport 不扩大 allowlist。MDM transport 复用同一 executor，精确预期 200/201/202/204，闭合解码 Identity 认证错误与 MDM 产品错误。响应 request-id/Retry-After 目前未暴露给页面，不宣称已消费这些元数据。

缺失能力使用明确的 `/api/v1/mdm-candidate/` 候选命名空间，**不是已发布的后端 API**。后端 owner 为 rss-mdm；后续真实合同落地时调整 domain adapter 和交互。基础候选：

| 请求 | 响应/语义 | 权限、失败、版本 |
|---|---|---|
| `GET /api/v1/mdm-candidate/workspace` | `{modules:[{id,source,available}]}`；id 为 devices/policies/software/security/operations，source 为 real/mock，available 为 true/false/null | 有效会话；后端决定每资源权限；无分页/写入；null 为导航未知。生产拒绝 mock source。401 清会话，403 拒绝，503 不可用；不自动重试 |

业务 DTO 必须经 decoder。读响应绑定当前会话，失效或旋转后的迟到响应不再呈现。业务 403/409/503 与协议错误不清除有效认证；401 才通知 session owner。业务并发派发与凭据轮换由同一 owner 双向协调，写入在派发时取得当前 CSRF，不全局重试；Identity no-replay 与 MDM 每操作精确幂等合同分别处理，未知结果需要显式核实。

新增 feature 在 `apps/mdm/src/features.ts` 注册普通路由和入口，业务模块不再装配 session/transport。导航提示不代表授权；真实页面请求仍由服务端复核。候选请求/响应、分页/CAS/批准状态及异常覆盖随对应业务项维护，不能把未实现服务标成已接入。

共享包的 UI 与纯会话入口见 [`@rss/auth`](../../packages/auth/README.md)。网关须直接面对客户端，并由后端将该网关 peer 配置为可信来源；示例覆盖客户端转发头，仅转发实际 peer 地址，并沿用 rss-mdm 的登录/API 限流、连接数、默认正文 16 KiB 及 10 秒客户端读取预算。精确路径 `/api/v1/resources/{id}/content` 与 `/api/v1/resources/{id}/uploads/{upload}` 的网关正文上限为 16 MiB，承载原生 POST 内容上传和 PATCH 分片上传；`/complete` 及普通 JSON 路径仍为 16 KiB，授权 PUT 和证书存档导入的 2 MiB 精确路径例外见各模块说明。前端 transport 和服务端继续按方法及内容类型区分 JSON/二进制预算，上传仍受路径限流和读取超时约束；429 返回安全错误码与 Retry-After，前端不自动重放写入。诊断日志只含关联 ID、状态和时延，不含 URL、header 或 body。

## 设备控制台

从工作区进入设备目录，可查看包含首次 pending 注册的授权设备投影；资产搜索另用已发布的异步查询，不在浏览器合并资产和注册列表来推断完整授权集合。平台尚未采集时显示未知。目录统计、详情、注册与批量预览由同一个 HTTP demo 状态持有，重置同时清除查询、组任务、幂等回执和分页。

搜索提交返回任务 ID，使用“读取任务状态”显式刷新；完成后读取结果和 facets。查询与组结果分页只根据服务端 nextCursor 结束，允许空尾页；不按返回行数推断完成。字段状态 known/null/missing/unsupported/deleted/conflict、来源和 lastKnown 分别呈现，时间不产生资产 TTL。asset_states 聚合计算字段数，不代表设备数。离开页面只忽略迟到响应，不取消服务端任务。

Manual、个人查询、组定义及归属编辑使用当前 revision；冲突保留草稿，重读服务器值后由操作者比较并再次提交。未知写入不自动重试；明确重放复用原 operationId 和完整正文。组条件先保存，再预览已保存版本；只有重算发布成员，预览不修改成员集，规则解释由服务端提供。

注册通过 Web Crypto 生成 256-bit Base64URL 口令，操作者确认安全交付后提交；表单立即清除口令，页面不持久化口令或完整秘密请求。未知结果保留非秘密操作身份；精确重放必须重新输入原口令。create/resume/cancel 使用 Idempotency-Key、HTTP 200；撤销凭据的已发布 wire 回执是 `operation_id`/`registration`，与 enrollment 的 camelCase 不混用。授权期限是注册凭据的期限，不是资产期限。设备侧 profile 安装、APNs、Agent 安装 ACK 与有效注册/通道就绪不同；本前端不代替设备协议下载、TokenUpdate 或采集验收。

ADE、Windows 自动化开通、入职、重新分配、丢失、退役、擦除及双通道引导均提供候选批量预览。冻结目标的设备版本、registration 和 generation，提交时重新复核；无权限、平台不支持、离线、旧世代、版本冲突逐设备列出。受理、下发、设备回执、实际效果和合规分别显示；demo 只受理模拟请求，效果与合规保持未知。详细执行记录由 #2546 配置与执行模块承接。

### devices-v1 候选合同

下表统一前缀 `/api/v1/mdm-candidate`，后端 owner **rss-mdm**。这些接口尚未由后端发布。响应都包含 `{contract:"devices-v1",tenantId,source:"real"|"mock"}`；客户端校验租户、目标与闭合字段，生产拒绝 mock。完整 DTO 由 `features/devices/clients/directory.ts` 定义，未来真实合同落地时直接替换该适配器，不保留旧 DTO fallback。

| 请求 | 输入 / 响应核心 | 授权与一致性 |
|---|---|---|
| `GET /devices?limit&cursor` | `{snapshot,items:[{id,name,platform,status,inventoryAvailable,revision,channels,owner,department}],nextCursor,statistics:{total,pending,windows,macos,withInventory}}` | 服务端授权目录；含无资产 pending，platform 可 unknown；冻结列表和统计，limit 1..1000，不透明 cursor 绑定投影 |
| `GET /devices/{id}` | `{device,readiness,capabilities:[{action,channel,support}],enrollments:[uuid]}` | 目标可见性由后端决定；readiness 为 unknown/pending_token/ready/offline；提示不是授权 |
| `GET /devices/{id}/hardware` | `{device,snapshot,items:[ResolvedField],nextCursor}` | 设备 inventory_read；沿用字段状态/来源/lastKnown 结构，硬件键属于此候选投影 |
| `GET /devices/{id}/software` | `{device,snapshot,state,items:[{id,name,version:ResolvedField}],nextCursor}` | 设备 inventory_read；state known/missing/unsupported/partial；空清单不等于未采集 |
| `GET /devices/{id}/history` | `{device,snapshot,items:[{id,at,event,operation}],nextCursor}` | 设备历史读取；event 闭合集，游标冻结时间与事件身份，不输出秘密 |
| `PUT /devices/{id}/assignment` | `Operation<{owner:string|null,department:string|null}>` → 当前 detail | 设备归属写权限；独立设备 revision CAS，不写成 Manual 资产字段 |
| `GET /groups?limit&cursor` | `{snapshot,items:[GroupSummary],nextCursor}` | 设备 group_read 与全租户 inventory_read；不是用户授权组列表 |
| `POST /devices/batch-previews` | `Operation<{action,devices:[id]}>` → HTTP 200 batch | 逐目标核实可见性、动作、平台/通道与世代；expectedRevision=0；id=operationId |
| `GET /devices/batch-previews/{id}` | 当前 batch | 同一租户/操作者可见的原预览或执行状态 |
| `POST /devices/batch-previews/{id}/execute` | `Operation<{confirmed:true}>` → HTTP 202 batch | 预览 revision CAS；重新授权并复核冻结版本/世代，不静默替换目标；逐目标受理不代表设备效果 |
| `POST /devices/batch-previews/{id}/cancel` | `Operation<{}>` → HTTP 200 batch | 只取消尚未执行的预览，不能取消或回滚已下发动作 |

`Operation<T>` 为 `{operationId,expectedRevision,input:T}`。batch 为 `{id,revision,action,phase,targets}`；phase 为 preview/accepted/cancelled；target 为 `{device,deviceRevision,registration,generation,blocked,execution,dispatch,receipt,effect,compliance}`。未知/不可见目标可没有版本或注册；blocked 为 null 或 stale_generation/offline/permission_denied/unsupported/not_registered/conflict。执行引用只有已受理目标才有。

候选权限名最终由 rss-mdm 定义；浏览器不授予权限或计算权威成员。候选错误沿用 MDM 闭合语义：400 malformed_request、401 invalid_identity、403 permission_denied、404 management_device_not_found/operation_not_found、409 operation_conflict、429 request_limited、501 action_not_supported、503 service_unavailable/operation_unknown。401 交给会话 owner；其余不清有效会话，不自动重试。模拟模式提供空、拒绝、离线、不支持、逐设备部分阻塞、冲突、未知提交和迟到响应；真实失败不进入模拟 handler。

## 配置、持续分配与执行控制台

策略模块提供 Scope、资源/内容上传、平台配置目录、持续分配、脚本入口、多步工作流、执行中心与显式工作流审批。普通脚本在资源库编辑参数和输出 Schema，再引用资源版本创建持续分配；没有独立 ScriptPlan 或普通脚本第二主体审批。策略页一次 CAS 保存来源、版本、动态 Scope、触发/频率、启停、退出行为和可选 UTC 有效窗口。Scope 成员为空时可以保存；可选预览不保存策略或创建运行。

后台成员计算序号与配置 revision 独立。“刷新进度”保留编辑草稿，“重新载入配置”明确替换草稿；409 后先比较最新配置再提交。未知写入只能显式重放原 operationId 与完整请求；Unknown 执行效果不会自动重发。取消在途运行不代表撤销已生效配置，取消请求/确认、受理/派发/回执/执行/效果/合规分别展示。既有执行记录保留，资源换版或设备身份变化不改写旧结果。

DemoControls 写入沿用应用唯一会话的登录/CSRF 校验，可注入 UTC 时间、设备注册或签到事件；事件只推进 HTTP demo 服务端，页面不持有调度器。设备注册写入和设备组任务发布后自动解析动态 Scope；时间与签到由模拟事件驱动。真实模式不启动该 owner，也不在真实失败后降级。演示重置会清除全部策略、运行、工作流、上传与分页状态；它不证明生产重启持久化恢复。

事件时间留空时，控件在每次提交前读取服务端场景 `asOf` 并加一秒；手填 Unix 秒用于推进时间或测试迟到证据。合规评估、保存、重算及审计共用安全场景时钟。远程同意和撤销填写申请 ID，其余支持观测填写原执行任务 ID；目标不存在、时间或状态不允许转换的同意/撤销事件返回 409，控件保留输入并显示未确认提示。事件显式推进的场景时间不会倒退；失败不代表其他观测或授权期限已回滚。

|---|---|---|---|
| Scope、资源/上传、原生操作读写 | 已实现 | 当前 HTTP V1 adapter；尚未运行真实 MDM 联调 | 待宿主/设备验证 |

### 正式 Policy 与脚本自助配置

脚本策略、持续配置和软件部署共享 `/api/v1/policies` 的正式模型与配置 owner。读取为 `{id,revision,version,versionId,enabled,definition}`；definition 为 `{scope,action,selfService?}`，action 使用 execution/native_collection/configuration/software/ensure_agent_installed/request_mdm_enrollment 闭合分支。删除 candidate assignments、computation、members、archive/cancel_run 与 candidate preview，不做双重解码。

持续配置在 Policy 页选择 configuration，加载已激活 Resource 的精确平台/架构/变体，并选择 retain/remove；移除能力由不可变原生 artifact 定义。Resource 配置 declaration 只持有 artifact，原生 target/apply/remove 位于上传内容；不再提供旧 firewall_version 快捷字段。配置目录的候选预检消费有效原生 claim；保存、操作 ID 和 mock 规划不证明设备效果，漂移与实际效果保持 unknown。

| 正式请求 | 语义 |
| --- | --- |
| `GET /api/v1/policies?after&action&limit` | `{items,nextCursor}`；UUID 顺序分页；脚本页筛选 execution，软件页筛选 software |
| `GET /api/v1/policies/{id}` | 当前配置；不是写入回执或执行结果 |
| `POST /api/v1/policies/{id}` | `Operation<{action:"put",definition,enabled}>` 或 enable/disable；operationId 与 expectedRevision CAS；200 正式 Policy |

execution 固定 Resource 的 id/version/platform/architecture/variant，Resource 唯一持有参数 Schema、字段类型和约束。Policy 仅保存每字段 fixed/value 或 input，动态参数要求 manual schedule，不复制 Schema。页面需先加载精确的已激活脚本变体，再编辑固定值或允许的输入来源；服务端复核权限、Resource、Scope 和资格。

selfService 保存 published、displayName、description、prerequisites、sideEffects、category、keywords、allowAi 与 riskLevel。第一次打开发布默认 allowAi=true、riskLevel=2；已有 false/1 保持原值。riskLevel 只允许 1/2。保存配置、发布/撤回、关闭 AI、禁用整个 Policy 分别处理；发布不创建任务，撤回不抹除历史，关闭 AI 保留人工自助，禁用整个 Policy 保留已发生的效果与证据。元数据、Scope 和启停只增加配置 revision；执行 action 改变才产生执行版本，software rollout 同样不改变执行版本。

写结果 Unknown 后保留 operationId 并禁止后续写入；读取当前配置不确认原操作回执，不自动重放。员工目录、调用和结果已由 rss-mdm 的 Agent runtime 契约持有，要求设备凭据与员工会话，由 Agent 消费；管理浏览器仅通过正式 Policy/Resource API 配置，不代员工执行或确认。Unknown 时可显式核对／重试完整原请求，同一身份、目标、operationId、revision 和正文经服务端幂等受理；此前未受理时会提交原操作。确认后重读当前配置再开放写入，读取配置本身不确认回执。

显式 loopback HTTP demo 使用同一份 Policy store、CAS 与回执，不保留第二份发布目录。启动及重置经相同 HTTP owner 写入四条演示策略：发布且允许 AI（风险 2）、发布且仅人工（false/1）、已撤回、已禁用；均引用真实的合成 Resource/Scope 数据。输出只标记合成，不声称真实 Agent 执行。生产构建排除 demo 模块，生产请求不回退 mock。

## 原生合规规则与评估证据

安全模块的合规规则与设备结论使用 rss-mdm #2469 的当前 `/api/v1` 合同，不加候选 envelope。后端拥有判定、平台注册来源、群组成员与事实新鲜度；页面不重新计算合规。无启用规则为 `unknown/no_rules`；`unknown`、`not_applicable`、`pending` 都不显示为合规。等待重评时 `current:null`，`previous` 单独标为上一轮证据；历史记录保持当时规则版本、任务 disposition、事实水位、字典版本、评估时间及来源引用。

| 路径（前缀 `/api/v1`） | 当前合同与权限 |
|---|---|
| `GET /compliance-rules?after` | `ComplianceRuleRead`；固定 50 条、按 UUID 的 after 分页；`{items,nextCursor}`。与历史 cursor 不互换 |
| `GET /compliance-rules/{id}`、`.../versions/{revision}` | `ComplianceRuleRead`；`{id,revision,definition}`，指定版本不可变。definition 为 name/severity/enabled/platform/target/criteria；target 为 all 或 1–16 个唯一群组；Criteria 非 null |
| `PUT /compliance-rules/{id}` | `ComplianceWrite`；`Operation<definition>`、revision CAS；200 `{id,revision,task}`，enabled 时 task 非 null；停用保留历史 |
| `POST /compliance-rules/{id}/recompute` | `ComplianceRecompute`；`Operation<{}>`，当前 revision 且启用；200 `{task}` |
| `GET /compliance-rules/{id}/tasks/{task}` | `ComplianceRuleRead` 及全设备 `ComplianceRead`；规则/版本/事实水位、phase、processed、completed、failure、diagnostic 分开呈现；queued/evaluating/published/superseded/failed |
| `GET /devices/{device}/compliance` | 当前设备 `ComplianceRead`；`{device,status,reason,rules}`，每规则保留 current/previous，不用历史替代当前结论 |
| `GET /devices/{device}/compliance/history?from&until&limit&cursor` | 当前设备 `ComplianceRead`；UTC 秒闭区间、limit 1–100（默认 50），不透明 cursor 绑定租户/主体/设备/时间范围；`{items,nextCursor}`，items 额外包含 task/disposition |

401 交给唯一会话 owner，403 拒绝访问，400 为无效请求，404 为不存在，409 为冲突，503 为不可用或结果未知。写入未知保留原目标、operationId、expectedRevision 和完整非秘密正文，只提供显式原操作重放；普通 GET 不解除未知锁定。修订冲突由操作者读取最新规则后重新编辑。敏感事实不放入合规证据；这里只展示来源、注册代次、epoch、快照、观测/接收时间、条件路径与结果。

Mock 初始没有合规规则。在安全模块新建规则、选择条件或显式空 AND 条件组，保存后读取任务两次推进合成评估。空静态群组可就绪且不匹配；动态群组须发布与当前规则/事实对应的成员集。事实或群组输入变化使当前结论待评估，可显式重新评估；未就绪冻结输入以 `superseded/group_input_pending` 结束。Mock 不实现生产 dispatcher 或设备采集；任务、证据与分页只验证前端合同和状态流，真实联调与产品验收仍待完成。

## 合规基线与例外候选

基线固定已发布 Scope 的 revision、原始设备成员与来源，以及每条原生规则的不可变版本。每次保存明确重新固定 Scope；后续范围变化或输入未就绪显示漂移，不静默替换目标。宽限使用绝对 UTC 截止时间，最多设置到当前服务器时间的 30 天后，改名不重置宽限。停用基线保留原生证据。

| 候选路径（前缀 `/api/v1/mdm-candidate/security`） | 请求 / 权限 | 响应与一致性 |
|---|---|---|
| `GET /baselines?limit&cursor`、`GET /baselines/{id}` | security.baseline.read，后端过滤资源 | 分页 `{items,snapshot,nextCursor,asOf}`，详情 `{baseline,asOf}`；baseline 含 id/revision/operation/createdAt/scopeRevision/definition |
| `PUT /baselines/{id}` | security.baseline.write；`Operation<{name,enabled,scope,rules:[{id,revision}],graceUntil}>` | 200 `{baseline,asOf}`；revision CAS，规则唯一且 1–100 条；保存须有已发布 Scope 与存在的规则版本 |
| `GET /baselines/{id}/devices?revision&limit&cursor` | security.baseline.read 及设备 compliance.read | `{baseline,revision,items,snapshot,nextCursor,asOf}`；版本不匹配 409；每设备包含原始 native 结论和每固定规则的 nativeStatus/drift/governance/request |
| `POST /requests` | security.exception.request；`Operation<{target,reason,validFrom,validUntil}>`，expectedRevision=0 | target 为 `compliance_exception {baseline,baselineRevision,rule,ruleVersion,device}`；id=operationId，200 `{request,asOf}`，初始 pending；理由 1–512 字符、有效窗口最多 30 天 |
| `GET /requests?device&state&limit&cursor`、`GET /requests/{id}` | security.request.read，后端过滤请求/设备资源 | 同样分页或 `{request,asOf}`；request 保留申请主体、有效期、独立审批/撤销主体与时间、pending/approved/denied/revoked/expired |
| `POST /requests/{id}/approve`、`.../deny`、`.../revoke` | approve/deny 要求 security.exception.review 且不同申请主体；revoke 要求 security.exception.revoke 且为申请人或审批人；`Operation<{}>` | CAS；批准重新校验基线/规则/范围/设备；过期先结算，不能用旧 revision 批准；200 `{request,asOf}` |

以上为 rss-mdm 拥有的候选合同，响应带 `{contract:"security-v1",tenantId,source}`，生产拒绝 mock，跨租户与未知字段拒绝。列表 limit 1–100（默认 20），不透明游标绑定主体、筛选和对象版本；分页保留原快照 `asOf`，过期后的旧页仍明确标为历史快照，新读取返回最新状态。401/403/400/404/409/503 分别为失效会话、无权、无效输入、不存在、冲突、不可用/结果未知。非秘密写入只允许显式原操作重放；GET 不解除未知锁定。基线冲突保留草稿，读取服务器版本供比较后可明确替换草稿；审批重放成功后再读取当前状态，不把缓存的批准回执当作仍有效授权。

仅原始 non_compliant、无漂移时可显示 grace/exempt/action_required；豁免还须匹配基线 revision、规则版本、设备及有效期。unknown/not_applicable/pending 不转成合规，批准或宽限不改写原生评估。请求、批准、拒绝、撤销及过期由共用审计 owner 记元数据，理由不进入审计。Mock 可在 Scope 发布和合规评估后新建基线、从设备行申请例外，再切换 reviewer 审批；不能自行批准，时钟推进会结算过期。

## 风险与整改候选

风险页呈现提供方、来源版本/发布时间、严重度、修复优先级、软件标识、受影响版本及修复版本。每设备评估独立保留评估 ID/版本/时间、affected/clear/unknown/not_applicable、原因、软件观测版本、补丁可用性以及证据来源注册代次。空列表、清单中存在软件、审批通过或设备命令成功均不等于风险消除；clear 只对应有来源证据的本次评估。历史评估不可变。Mock 使用明确的 `DEMO-RISK-2026-001` 和合成提供方，没有虚构真实 CVE。

| 候选路径（前缀 `/api/v1/mdm-candidate/security`） | 请求 / 权限 | 响应与一致性 |
|---|---|---|
| `GET /risks?limit&cursor`、`GET /risks/{id}` | security.risk.read | 既有 security-v1 分页或 `{risk,asOf}`；risk 保留 provider、revision、publishedAt、software 与独立 severity/priority |
| `GET /risks/{id}/devices?limit&cursor`、`.../devices/{device}`、`.../devices/{device}/history?limit&cursor` | security.risk.read，后端过滤设备资源 | 设备评估分页、当前 `{assessment,asOf}`、历史分页；cursor 绑定主体/风险/设备；不存在为 404，未知输入保留 unknown |
| `POST /risks/{id}/devices/{device}/reassess` | security.risk.assess；`Operation<{}>`，expectedRevision 为当前评估 version | 200 `{assessment,operation,asOf}`，新评估 version+1；读取当前来源输入重新评估，历史不改写；未知提交只显式原操作重放 |
| `POST /requests`、`.../{id}/approve` 等 | security.remediation.request/review/revoke，仍要求独立审批主体 | 新闭合 target `risk_remediation {risk,assessment,assessmentVersion,device}`；创建和批准绑定精确当前评估及可用补丁，过时评估返回 409 |
| `POST /requests/{id}/dispatch` | security.remediation.dispatch 且为申请主体；`Operation<{}>`，CAS 绑定 approved request revision | 200 `{action,asOf}`；id=operationId，独立 action revision=1；重新核对有效期、当前评估、唯一活动 Agent 注册与 security.remediate.v1 能力，固定 source 和 deadline；501 为能力不支持 |
| `GET /actions?device&request&limit&cursor`、`GET /actions/{id}` | security.action.read，后端过滤设备/请求资源 | 既有分页或 `{action,asOf}`；action 保留 request/target/source、createdAt/deadline/resultAt/detectedAt，summary 由统一执行 owner 投影 |

共用 security-v1 envelope、分页和错误规则。整改执行 origin 为 `security {request}`，同一个执行 ID 可从安全执行页和既有执行中心查询；页面不复制执行状态。派发提交结果未知时只重放原操作，禁止另建相同请求的执行；同设备/风险有未结束或未知效果时，新的批准也不能绕过执行占用。已知失败后重试须重新申请与审批。过期或撤销阻断尚未下发的任务，不推断已经产生的设备效果被撤销；注册/能力变化使未开始任务失败，已运行结果保留未知，旧代次检测不能确认新设备状态。

Mock 中先由 demo 在风险设备详情申请，再切换 reviewer 批准，切回 demo 显式派发。模拟控制的 `security_result` 绑定设备和原执行 ID，只推进设备回执/命令结果；`security_detect` 还须晚于该结果且来源代次一致，才记录独立补丁观测。页面再显式“重新评估风险”，风险 owner 使用提供方与新观测生成评估，只有此证据可解除 risk_affected 告警。检测事件不会直接改写风险结论。两种事件均为开发 HTTP 场景输入，生产不提供，也不实现真实扫描、下载或补丁安装。

## 软件来源与 Resource 合同

企业来源页使用 `/api/v1/software/sources/{id}/revisions/{revision}` 的 GET/POST，登记 definition 包含 id、固定 revision、private/winget/brew、无凭据 location 和 publishers。批准/撤回提交审查 evidence，并使用当前 admission.revision 做 CAS。来源批准与版本批准分开，`/api/v1/software/resources/{id}/versions/{version}` 使用独立 admission；企业准入无需先导出 WinGet REST 或 Brew Tap。撤回准入阻断新的安装，不自动卸载，也不证明外部源已经删除。

软件 Resource 声明采用现行 `{kind:"software",definition:SoftwareSpec}`，不接受已退出的扁平声明。definition 保留精确来源快照、MSI/PKG/RSS ZIP/WinGet/Brew 格式、完整文件集、显式安装和卸载身份/参数/预算、独立检测、重启/降级/已有软件所有权策略、固定依赖及 ZIP manifest。通用资源编辑器的“文件元数据”生成主文件长度和摘要；先分别保存各平台/架构/变体草稿，再一次提交完整不可变版本。同一坐标重新保存会替换草稿，提交前也可移除。辅助文件在声明中给出，上传时选择对应文件引用，所有文件仍由 Resource 持有。目录链接可直接打开指定 Resource。文件摘要和上传均按 4 MiB 分块读取，不整文件驻留内存；单块 HTTP 边界仍为 16 MiB，JSON 请求维持 16 KiB。软件包总大小由服务端内容配置限制，脚本仍限制 16 MiB。

内容上传使用原生 `/api/v1/resources/{id}/uploads/{upload}`：POST 以 version/variant/platform/architecture/可选 artifact 创建固定上传会话，GET 读取 binding、offset、expires、complete，PATCH 以 offset 追加原始字节，POST `/complete` 校验并完成内容入库（201）。`upload_offset_conflict` 为明确 409，页面不自动重试；中断后重新选择同一文件并明确继续，重新读取原会话的服务端 offset。文件大小和摘要必须与冻结 binding 一致。刷新页面后可在原 Resource 填入上传 ID 恢复；不把文件或上传状态写入浏览器存储。导航/卸载中止在途请求并停止后续块写入。会话 complete 仅表示临时内容已校验，不替代数据库绑定回执；只有完成接口 201 或 `/content/operations/{upload}` 的 committed 回执确认入库，准入/激活仍独立。mock 复用 Resource 内容 owner，隔离主体、校验固定绑定、offset 和完整摘要；重置清除上传会话与内容回执。

外部发布客户端使用 `/api/v1/software-sources/{source}/candidates/{id}`；Test/Pilot/Production 的验证、审批、授权、发布/恢复/重试/撤回均使用后端合同，publish/recover 绑定 publication 摘要与 attempt。`unknown` 不解释为失败或成功，不自动重发。

软件分配客户端使用现行 `/api/v1/policies`、`/policies/previews`、`/policies/{id}`、`/policies/{id}/devices` 和 `/policies/{id}/software/rollout`；执行证据走 `/policies/{id}/runs` 及具体 task。意图为 required_install / available_install / explicit_uninstall；定义绑定确切企业批准 operation、Scope 和逐平台变体。暂停为 disable，恢复为 enable；当前后端没有独立批次暂停合同。原生预览分页用 after + scopeResult，运行分页用 afterAt + afterId，不与候选 cursor 混用。执行、安装退出码、检测、待重启与最终效果分别解码。

发布页面支持固定候选、逐环验证/批准、发布者授权、发布、精确尝试对账、确认未应用后的新尝试和撤回。演示发布绑定为 `demo-winget` / `demo-brew`，与企业来源 ID 独立；使用 `reviewer / demo` 审批并绑定发布者主体 `22222222-2222-4222-8222-222222222222`，再由 `demo / demo` 授权和发布。服务端拒绝同人审批发布与跳环晋级；这些合成身份不授予真实权限。candidate 初始修订号为 0。GET 不含操作回执，不能解除 Unknown 写入；页面保留原操作供精确重放，发布/恢复还可显式对账同一 publication + attempt。撤回后读取仍保留历史发布结果，`deprecated` 只表示停止晋级；仅成功撤回写入回执确认该环的撤回请求，页面不从 disposition 推断外部内容已删除。

| --- | --- | --- |
| `GET /items?cursor&limit`、`GET /items/{id}` | software.read | 分页 snapshot/items/nextCursor 或 item；item 含 id、revision、operation、definition |
| `POST /items/{id}` | software.catalog.write | Operation `{action:"put",definition}`；definition 含 title、description、enabled、原生 resource binding、scope、admissionOperation、schedule、runLifetimeSeconds；200 item，独立 CAS 与精确操作回执 |
| `GET /requests?phase&cursor&limit`、`GET /requests/{id}` | software.request.read，服务端约束可见设备/申请人 | 分页 snapshot/items/nextCursor 或 request；游标绑定 phase 与固定分页快照 |
| `POST /requests/{id}` | software.request.approve 或 software.request.cancel，并重新检查对应设备的 SoftwareDeploy 权限 | Operation `{action:"approve"或"deny"或"cancel",note}`；同步 200 request；revision CAS、同 actor/path/body 精确重放，不提供管理员伪造员工请求入口 |

请求含 id、revision、operation、requester、device、createdAt、固定 item{id,revision,title,resource}、phase、decisions、policy{id,versionId} 与 execution。phase 只表达 pending/approved/denied/cancelled 的业务决定，execution 仅链接最新原生 task；它不复制运行或效果权威。每次决定记录 actor、时间和说明。审批只允许 pending，并重新检查目录修订、启用状态、已发布范围成员、活跃注册/软件能力、固定资源和精确企业准入。申请人不能批准自己的请求。目录换版后旧请求不能静默改绑；管理员应拒绝旧申请，由员工重新申请。

候选要求批准操作在服务端绑定一个不可由普通配置写接口改写的单设备 Scope 和 available_install Policy。HTTP mock 复用已有 owner，并在绑定失败时撤销未使用的内部 Scope；原生管理读接口和执行中心仍可查看这些对象，编辑应从请求处理入口进入。保存目录、收到申请、批准请求都不代表运行开始，后续 Agent poll 领取任务并等待本地用户继续。取消 pending 请求只关闭业务申请；取消 approved 请求由同一 owner 禁用关联 Policy，不抹去运行证据、未知效果或重启需求。关闭目录不撤销既有批准，需要逐个取消请求。

Unknown 后只有 request/item 的 operation 与原提交一致，或同操作写入回执，才能解除前端写入限制。403 保留拒绝状态，409 先读取对比后重新决策；不把目录审批、设备命令重授权和企业准入相互替代。生产接入必须由后端完成请求者身份、设备范围和服务端生成对象的写入保护；mock 权限与 device.owner 合成身份不作为真实授权证据。

演示时，保存一个启用的自助条目，复制条目 ID，在顶部控制选择“本地用户提交安装申请”、指定已在范围内且具备软件能力的设备；审批队列即可读取该合成申请。批准后通过 check_in 模拟领取、通过“本地用户继续安装”模拟开始，再用 check_in 回报结果。界面可分别观察批准、waiting_user、运行和效果；同一条目修订下重复的未结束申请不会重复创建。


## OS 更新与第三方补丁候选

更新页选择固定的 Windows/macOS 更新或已准入的第三方软件 Resource 版本，定义总 Scope、延迟天数、最迟开始安装时间、维护窗口以及 OS 通知与重启策略。OS 延迟从版本发布时间计算，第三方补丁延迟从本次部署开始计算。截止时间不覆盖维护窗口、不代表设备必然已安装；跨午夜窗口沿用原生软件日历解释。安装前需单独扫描缺口，未知、未采样和无能力设备均不计为已更新。

下列接口归 rss-mdm 更新管理域，使用 software-v1 envelope；当前后端没有 OS 更新或补丁扫描控制器，本前端没有把它们伪装成现有 firewall/profile_install 操作。第三方安装复用当前 Resource、准入、原生 software Policy/Run；候选负责扫描与编排，不复制运行权威。OS 执行以 `update {ring}` origin 投影到既有执行中心。

| 候选路径（前缀 `/api/v1/mdm-candidate/software/updates`） | 请求 / 权限 | 响应与一致性 |
| --- | --- | --- |
| `GET /releases` | update.read | items：固定 id、platform、title、version、releasedAt、source；不含 latest 别名 |
| `GET /?cursor&limit`、`GET /{id}` | update.read + 可见设备范围 | snapshot/items/nextCursor 或 ring；不透明分页快照；ring 含 id、revision、operation、definition、scopeRevision、devices、policy |
| `POST /{id}` | update.write；install/retry 另需对应设备的更新/软件部署权限 | Operation 输入 put `{definition}`、scan/install/pause/resume 或 retry/reconcile `{device}`；200 确认控制器受理，设备任务异步推进；revision CAS 与 actor/path/body 精确重放 |

定义 target 是闭合 OS `{kind:"os",release}` 或 third_party `{kind:"third_party",resource,admissionOperation}`。其余字段为 title、scope、platform、enabled、deferDays（0–365）、deadline（UTC Unix 秒）、notifyMinutes（0–10080）、reboot（user/maintenance）和 window。maintenance 重启须配置窗口。当前第三方原生协议只报告重启需求，因此第三方定义只接受 notifyMinutes=0、reboot=user，不承诺自动重启或更新通知。操作系统通知时间与 rebootRequestedAt 独立记录；请求重启不代表设备已重启。

扫描冻结范围修订和每台设备的 registration{id,generation,source}；必须有明确且同代次的更新能力，不能从资产版本或 channels 推断。缺口回报含 gap、observedAt、source；无回报为 unknown/unavailable，只有独立回报才给出 missing/installed/not_applicable。安装重新检查已发布 Scope 成员、源注册代次、能力、固定包准入和 24 小时内扫描证据。OS 阶段依次为 queued、downloading、installing、waiting_reboot、verified；退出阶段与 effect 分开。原尝试的执行记录在扫描、修改、重试后仍保留。

暂停取消尚未开始的 OS 任务，正在运行的任务先进入 cancel_requested，设备确认后仍保留 unknown 效果；等待重启的事实不被抹去。已知失败可显式 retry，新尝试重新检查授权并保留历史。Unknown 只能显式 reconcile 原尝试，再等待独立设备回报，不创建新安装；仍无证据时继续 unknown。扫描不能覆盖尚未结束或未知的效果。修改定义前同样需处理原任务。恢复启用只开放后续部署，不自动重放已取消任务。

第三方部署在服务端创建仅含已确认缺口设备的受保护 Scope 和 required_install Policy，复用自助请求使用的内部对象创建能力；普通写接口不能改写。原更新 Scope 或准入撤销时，更新 owner 在 Agent 推进前停止关联 Policy。每台设备的阶段和实效投影自原生 task，详情链接到既有执行中心；未知软件运行仍需原生设备证据，更新控制器不伪造对账成功。重新扫描前必须先结束当前执行，后续部署创建新的受控分配。

候选错误复用 400/401/403/404/409/503 语义。丢失受理响应时保留原 operationId；仅对应 operation 的读取或精确重放可解除前端写入禁用。重新登录、网络恢复、读取其他环都不重发写操作。分页快照保留其创建时结果，实时核对用指定 ring 读取。

演示 OS 更新源只有 `demo-windows-quality-1` 与 `demo-macos-quality-1`，不是实际厂商更新。先发布 Scope（Windows 可用 device-01，macOS 可用 device-02），保存更新环并扫描，再注入 check_in 得到合成扫描回报。部署后按通知提前量/窗口推进时间，继续 check_in 模拟下载、安装和待重启；software_reboot 注入独立重启后检测。maintenance 策略在窗口内的 check_in 只记录重启请求，仍须后续检测才验证成功。partial 模拟已知安装失败，unknown 模拟实效不明；通过原任务对账再注入 normal check_in 才产生明确回报。unsupported 无执行资格，offline 不推进。所有来源、时间和设备效果均为合成事实，未完成真实 Windows/macOS 更新验收。


## AgentBootstrap 与两条独立来源策略候选

来源策略页有两个独立动作：`install_agent` 经现有 Windows/Apple MDM 来源投递受信任 AgentBootstrap MSI/PKG；`request_mdm` 经现有 Agent 来源向本地用户提供 MDM 注册指引。每条策略有自己的 Scope、配置修订、启停与任务；没有双向 bootstrap session、统一凭据或跨来源的完成状态。source registration、任务投递/回执、安装检测、target registration 和 Agent binding 是独立事实。已有 Agent 不自动证明一次安装任务成功，安装 ACK 也不创建 Agent 注册。

| software-v1 路径（前缀 `/api/v1/mdm-candidate/software/bootstrap`） | 请求 / 权限 | 响应与一致性 |
| --- | --- | --- |
| `GET /?cursor&limit`、`GET /{id}` | source_policy.read + 设备可见范围 | snapshot/items/nextCursor 或 policy；固定分页快照，指定策略读取最新观测 |
| `GET /{id}/attempts/{attempt}` | source_policy.read + operation.read + 该设备证据权限 | attempt 原尝试证据；保留失败、取消、换代前的冻结来源，不从当前策略配置反推历史 |
| `POST /{id}` | source_policy.write；dispatch/retry 另需 AgentBootstrapInstall 或 MdmEnrollmentGuide 权限 | Operation 输入 put `{definition}`、evaluate/dispatch/pause/resume 或 retry/reconcile `{device}`；200 确认控制器受理，设备异步推进；revision CAS 与 actor/path/body 精确操作回执 |

后端 owner 为 rss-mdm 来源策略/软件管理域。当前没有原生 AgentBootstrap 或注册指引任务接口，因此它们是候选，不能复用已有 firewall `profile_install` 或一般 Agent 软件策略来启动尚未存在的 Agent。定义共用 title、scope、platform、enabled，action 是闭合分支：install_agent `{resource,admissionOperation,userAction:"required"或"silent"}`；request_mdm `{instructions}`。指引是至多 4096 字符的纯文本，不携带密码、令牌或注册授权；请求不接受 credential、enrollment 或审批字段。生产后端必须校验其发布系统持有的受信任 Agent 发行身份、签名、固定文件摘要及企业准入，不能以浏览器提交的包名或已入库的一般软件代替发行信任。此页面不提供另一个注册审批或凭据表单。

评估使用既有 Scope owner 发布的成员，目标行分别返回 device、当前 source{registrationId,generation,source}、admission、attempt、target（现行 v3 Registration 投影）和 binding。来源资格须有明确的同代次 bootstrap/注册指引能力；Agent 来源另须有效 v3 binding，不能仅由设备 channels 判断。目标 Agent 的 missing/unsupported/ready/ambiguous 独立于注册；目标为 MDM 时 binding 为 not_applicable。目标注册读现有设备 owner，设备页 `?tab=credentials` 可直接打开唯一注册视图；授权/恢复跳转 `device-enroll?device&source`。

每次任务固定 kind、policyRevision、来源 registrationId/generation、createdAt、deadline（受理后 24 小时）。投递 delivery、phase、installation、acknowledgedAt、detectedAt、code 分别保存。MDM 安装先等待本地用户（或按显式 silent 策略运行），设备 ACK 后 installation 仍 unverified，必须由后续独立检测改为 present。注册指引的 installation 永远是 not_applicable；本地用户继续和命令回执都不证明目标已注册。当前来源和尝试冻结来源均在 UI 可见。旧来源换代后，未开始任务失败，运行中/未验证效果保留 unknown；绝不静默换绑新代次。

暂停停止 queued/waiting_user，运行中的结果保留 unknown；恢复只开放后续受理，已停止任务须显式 retry。retry 仅接受已知失败或启动前停止，并重新核对当前来源、范围、能力和包准入；旧证据由 attempts 读接口和执行中心保留。Unknown 仅 reconcile 原 attempt 后等待独立回报，不建立第二次安装。定义或评估不能覆盖未结束或未知尝试。同一设备同类动作存在未结束尝试时，不允许另一策略重叠执行。执行中心增加 `bootstrap {policy}` origin，摘要仍不把任务成功称为合规或注册就绪，详情读取原 attempt owner。

HTTP mock 中 Agent 发行 allowlist 仅是合成 `RSS.DemoAgent` 包标识，以及已激活/准入、system MSI/PKG、空参数、单文件、无脚本检测或外部依赖的受限声明。这是演示规则，不是生产验签或软件可信证据。可在私有 Resource 创建该合成包，再在本页绑定；Windows 使用 device-05 的 MDM 来源，Agent 发出 Windows MDM 指引可使用 device-09。macOS 路径选择 PKG 和 Apple MDM 来源。evaluate 后 dispatch，check_in 模拟接收，bootstrap_continue 模拟本地继续，下一次 check_in 模拟命令回执；bootstrap_detect 模拟独立检测或原任务对账。partial 产生失败，unknown 保留未知，offline 不推进，注册换代检查不会改写历史坐标。

独立注册演示必须先在设备注册页面创建 pending Enrollment；顶部控制的 enrollment_bind 带该 Enrollment ID 和设备 ID，只能在其 5 分钟授权期内绑定正确设备。由设备 enrollment owner supersede 同一来源旧注册并递增该来源代次，不自动生成 Agent binding。随后可注入 agent_binding，为已注册且平台明确的 Agent 单独报告 v3 binding，以及明确支持或不支持的软件能力；缺少注册时无效。两类事件均仅限显式 mock 设备来源，使用单向时间，不接受来源策略代发凭据。它们不会让软件页面拥有注册权威，也不证明真实设备已注册。


## 设备证书候选

`security-v1` 证书记录绑定 device 与 profile（id/name/platform/protocol/issuer/purpose），严格区分 issuance 与 installed。仅消费公开元数据 serial/fingerprint/subject/notBefore/notAfter；不接收或展示私钥、CA 密码、CSR 或下发内容。当前合成 profile 为 Windows SCEP / macOS ACME 设备身份用途，协议执行不在前端交付内。

| 候选路径（前缀 `/api/v1/mdm-candidate/security`） | 权限 / 一致性 | 响应与异步语义 |
| --- | --- | --- |
| `GET /certificates?device&limit&cursor`、`GET /certificates/{id}` | security.certificate.read，按设备资源过滤；分页绑定主体/筛选并冻结 asOf | security-v1 分页或 `{certificate,asOf}`；必填 id/revision/device/profile/source/issuance/installed/validity/evaluatedAt |
| `POST /certificates/{id}/issue` | security.certificate.issue；Operation 空 input、CAS、精确回执 | 请求签发或续期，issuance `{operation,state,requestedAt,resultAt,credential}`；state requested/issued/failed/unknown；受理不产生证书，未知占用原尝试 |
| `POST /requests` 与审批路径 | security.certificate.deploy.request/review；申请者与审批者分离 | `certificate_deploy {device,certificate,certificateRevision,fingerprint}` 固定已签发证书和记录版本；无效、过期、错指纹或来源不可执行时拒绝 |
| `POST /requests/{id}/dispatch`、`GET /actions[/id]` | 既有安全执行权限，批准有效期/主体/目标与设备注册能力再次校验 | 单一 action/execution owner，冻结 mdm.windows/mdm.apple 注册代次及 certificate.deploy.v1 能力；受理、结果和安装观测分别展示 |

安装观测包含 credential/observedAt/source。服务端根据有效期和当前注册来源报告 unknown/not_yet_valid/valid/expiring/expired；来源变化保留历史证书元数据但当前有效性变成 unknown。Mock 提前七天告警，首次合成设备证书一小时后到期，其他设备初始无安装观测；缺失不能推断已保护。到期状态随服务端时钟推进，唯一运营 owner 持有 certificate_expiry 告警，确认不会解除告警。

演示先对签发 operation ID 注入 `certificate_issued`（支持失败、未知及同尝试后续结果），再单独申请/批准/派发部署。`security_result` 只表示命令结果；之后对原执行 ID 注入较晚、同设备/注册代次的 `certificate_detect`，才更新 installed。新证书签发和命令成功都保留旧证书及其到期告警；新设备观测证明有效证书已安装才解除。旧指纹、过期候选、乱序和旧注册证据均不能证明替换成功。

写入使用既有非秘密精确回放：未知结果保留原正文，GET 不解除未知锁，成功回执后再读当前状态。400 无效正文、403 无权、404 不存在、409 版本/生命周期冲突、501 无能力、503 不可用或提交未知；已知失败可在读取当前版本后发起新签发，未知签发必须等待原结果。审计仅记录证书/设备/版本/操作引用和结果，不保存申请理由或凭据正文。真实证书服务与设备效果仍由 rss-mdm 和设备侧验收。


## 终端支持与体验候选

支持流程继续使用同一 `security-v1`、请求审批 owner 和安全 action/execution owner。浏览器不拥有 OS 权限判断或远程用户同意，也不接受任意脚本、命令和诊断路径。目标能力来自服务端设备 context 的平台、Agent 注册代次和独立 capability；设备数据可读不代表可执行支持操作。

| 候选路径（前缀 `/api/v1/mdm-candidate/security`） | 权限与闭合输入 | 响应 / 状态 |
| --- | --- | --- |
| `GET /support/devices/{device}` | security.support.read，资源授权 | `{context,asOf}`；context 包含 device/revision/platform/source/capabilities/accounts/programs/evaluatedAt；program 为 id/name/path/sha256/publisher，能力为 elevation/diagnostics/remoteModes |
| `POST /requests` 与独立 approve/deny/revoke | security.support.request/review；Operation/CAS，申请者不能自批；窗口最多一小时 | elevation target 固定 device/contextRevision/account/完整 program 身份；diagnostics 固定 artifacts 与 retentionSeconds（最多七天）；remote_support 固定 device/contextRevision/mode(view/control)；requester 从会话推导，远程 request ID 即唯一 attempt |
| `GET /support/requests/{id}` | security.support.read，关联设备权限 | `{support,asOf}`；support 为 request/requester/target/source/action/details；action 仅引用已有执行 ID，details 分别为授权与用户运行、诊断材料、用户同意与会话观测 |
| `POST /requests/{id}/dispatch` | security.support.dispatch，当前主体必须为申请人；重新校验批准/窗口/目标/注册/能力；远程必须有本次设备用户同意 | 既有安全 action 的精确非秘密回执；一项申请最多一个 action，失败重试需新申请；未知尝试保持占用，普通 GET 不解除写入未知锁 |
| `GET /support/devices/{device}/experience` | security.experience.read，资源授权 | `{experience,asOf}`；device/window(from,until)/source(provider,registration)/evaluatedAt/metrics；每项显式 value/state/sampleCount/denominator/unknownCount |

提权只针对 context 中观察到的账户和精确程序 SHA-256/路径/发布者元数据。批准和命令结果不等于设备已授权；独立 `support_detect` 才记录 grant.available。`elevation_used`/`elevation_ended` 分别表示设备观察到用户运行/进程结束。申请过期或撤销阻止新使用；未确认的授权撤回与正在运行进程均为 unknown。`elevation_revoked` 只证明设备撤销 grant，仍不证明旧进程结束。支持状态记录观测事实，唯一 action 持有 ExecutionSummary；当前不确定性及撤回确认更新该摘要，页面不另存执行生命周期。

远程协助为 attended view/control。独立审批后，设备侧合成 `remote_consent`（task 为 request ID、active 为接受/拒绝）绑定原申请的 helper/requester、device、mode、attempt 和注册来源。同意最多五分钟且不超过申请窗口；管理员没有同意 HTTP API。未同意、拒绝、过期、撤销或旧来源均不能派发。重试新申请不会继承旧同意；已有会话期间也不能另起同目标会话。命令成功后仍须独立设备 `support_detect` 才表示 connected。`remote_revoke` 使尚未结束的会话变成 unknown，`remote_ended` 才确认 ended；无屏幕、按键、录制、连接凭据或 launch token URL。

诊断只允许 system_events/inventory_summary/network_summary 三类摘要。`support_detect` 记录采集时间和合成 records/bytes 元数据，之后 `diagnostic_uploaded` 与 `diagnostic_scanned` 分别确认上传和扫描；乱序不能跳阶段，扫描支持 clean/blocked/unknown，保留期从采集时间计算，到期不再显示 ready。本前端只展示合成摘要，不提供真实 archive 下载或内容传输。

上述支持事件除 consent/revoke 使用申请 ID 外，都使用唯一 action ID，同时核对 device、当前注册来源和时间顺序。演示控制器是开发/演示入口，不是产品设备事件 API。元数据审计复用 operations owner，保存主体/动作/对象/操作/结果，排除理由、诊断原文、程序输出和会话内容。已知错误复核当前版本后可重新申请；未知写只显式重放原 Operation。400/403/404/409/501/503 与既有候选错误语义一致，真实接口失败不会回退 mock。

体验数据来自独立合成 telemetry provider，不从安装清单或当前磁盘字段推出趋势。boot_seconds_p95 单位秒、分母为预期启动事件；crashes_per_100_sessions 是每百次有效应用会话的崩溃数、分母为预期应用会话；disk_free_percent 为磁盘空闲百分比均值、分母为预期磁盘采样。服务端明确 complete/incomplete/unknown；缺失覆盖不补零，没有可验证来源时值和未知分母为 null。窗口固定于模拟提供方观测，读取不会生成更新的样本；来源变化会使当前证据 unknown。页面直接展示来源值与口径，无浏览器聚合或真实遥测引擎。

设备详情提供合规、材料、证书、支持、体验及安全执行/申请和运营审计/告警的双向入口。原生合规问题可进入既有配置、Scope 和执行流程；修复效果仍需新设备证据和显式原生重评，不因页面导航或命令成功改变结论。安全整改与远程支持组合测试使用生产 domain clients 经模拟 HTTP 边界消费 DTO，并验证切换 security 或 operations 为 real 后，相关 native security、security candidate、共享 executions 和运营投影统一拒绝读取模拟结果。当前仅完成前端交互与 HTTP mock 验证，未运行真实 MDM/Agent/CA/保管库/遥测验收。

### 当前授权 v1

`GET /api/v1/authorization` 返回实例/租户/主体及后端计算的有效 grants；规则和用户组列表使用 `after=UUID`，每页最多 100，不提供冻结快照。用户组列表返回 memberCount；完整成员分页使用 `offset`/`expectedRevision`。组编辑先读取同 revision 的全部成员，再整体 PUT，不能用当前页覆盖整组。

规则/组 PUT 使用 `{operationId,expectedRevision,value}`，新建 revision=0，删除 value=null，200 返回 `{id,revision,deleted}`。UUID tombstone 不复用。重放也须重新授权；Unknown 只允许显式原操作/原正文重放，409 保留草稿并比较服务器版本。可能移除管理访问的变更须先确认职责交接；没有内建防锁死或自动恢复授权。

客户端、demo ingress 与网关示例只为 `/api/v1/authorization/{rules|user-groups}/{uuid}` PUT 支持 2 MiB JSON；证书存档导入 POST 的独立例外见下文，其余 JSON 仍为 16 KiB，内容上传沿用既有 16 MiB。部署现有网关时需同步此精确路径预算。

### #2548 修复后的协议与事实约束

候选批量设备操作在 HTTP mock 组合根读取现有批次 owner 的事实，并在 preview、execute、cancel、read 和精确回执重放前重新检查当前授权。wipe 使用逐设备 `device_wipe`，reassign 使用逐设备 `inventory_assign`，cancel 使用逐设备 `operation_cancel`；尚无真实动作映射的其它候选生命周期动作明确使用 Mock 管理决策 `authorization_write`。所有目标另需 `inventory_read`，任一目标不满足则整次请求拒绝；不新增真实 Permission，也不把历史 preview 当作授权凭据。

管理写入回执绑定 operationId、目标 ID、CAS 后继 revision；新报表、维护任务和投递的 ID 为 operationId、初始 revision 为 1，投递另绑定 connector。精确重放仍返回原始提交回执，页面随后读取当前事实。报表完成审计保持 `report` 对象类型。

投影积压和 Agent 健康告警复用诊断事实；普通场景的 Agent 健康 unknown 不推断为 healthy 或告警解除。连接器停用状态优先于异步投递健康，投递历史独立保留，重新启用时恢复最后一次业务投递的已知事实。最后一次业务完成由投递 owner 在显式 tick 中按观察顺序记录 delivery ID；同时间戳也按该顺序，独立投递链的 attempt 不参与新旧排序。该索引只引用现有投递事实，reset 时清除，不另存健康缓存。表单允许清空公开引用并提交 null，协议解码仍拒绝空字符串。连接器 query id 变化清除旧目标、草稿、投递和待核实回执；迟到响应由现有 useOperation 拦截。

## 证书存档（#2641，真实 API）

安全管理的证书存档页面消费 rss-mdm `/api/v1/certificate-archive`，使用现有登录会话与共享 HTTP 执行器。租户路径只定位资源；后端核验 `certificate_archive_read/write/unlock/export` 的 Tenant scope 权限。页面支持导入、生成 CA/私有 HTTPS/CSR/APNs CSR/SCEP 前置模板、完整版本与手工导出，到期信息可在锁定状态读取。

导入最多 16 个文件、原始材料合计 1 MiB；Base64 JSON 正文预算为 2 MiB。部署时须同步网关精确路径 `/api/v1/certificate-archive/import` 的 POST 例外（`client_max_body_size 2m`），其余存档路径仍为 16 KiB；限流、读取超时和禁止自动写入重放继续适用。

主密码、文件密码和导出材料只保留在当前组件内，提交后清理输入；切换会话、离开页面、锁定、换主密码或解锁到期会清除暂存文件及文件密码并释放下载 URL。初始化、换密码及其他持久写入使用 `Idempotency-Key`；结果未知时只查询原操作，不自动重放秘密。主密码的持久保护、数据库恢复与全项目证书用途以 rss-mdm `crates/certificate-archive-service/README.md` 为准。该页面不属于 security-v1 候选合同，没有 mock 回退，不替其他服务装载证书或实现设备 PKI。
