# MDM 与 Identity 独立前端

## 应用与业务边界

`apps/mdm` 是唯一生产 MDM，使用 React、TypeScript、Ant Design；Identity 与独立 Device Access 分别构建部署，使用各自的 React + Ant Design 组合。MDM 不以其它前端应用作为运行依赖。

MDM 业务核心持有模型、用例与窄 ports，`@rss/mdm-http` 实现正式生成操作的绑定，应用 runtime 装配一次会话、CSRF 和领域用例。`@rss/api` 执行 HTTP。当前生产依赖由 manifest、exports 和既有 ESLint 边界共同表达，不维护另一份 Vite 依赖矩阵。

Group、Scope、Policy、Resource、Execution 的求值、授权、准入与事务权威归后端。目录分页不代表全集，配置保存不代表设备已执行，完整历史结果不代表当前健康。前端分别表达 CAS 冲突、提交未知、业务拒绝、不可用和无数据。

## 构建与宿主

```bash
pnpm install --frozen-lockfile
pnpm dev:mdm
pnpm build:mdm
pnpm image:mdm --tag rss-mdm-web:my-version
```

`pnpm build` 构建 Identity、MDM 和独立 DA；`make ci` 收集类型、lint、格式、测试及各应用构建的全部失败。生产 MDM 使用唯一 React 构建扫描，关闭 source map，隔离显式 demo。

镜像只通过 8080 HTTP 提供静态资源。rss-mdm 网关拥有 TLS、API、静态宿主配置和安全响应头。MDM 必须从同源 HTTPS 入口加载两份严格配置：

- `/api/v1/identity-host/config.json`：`canonicalOrigin`、`oidcEnabled`。
- `/api/v1/mdm-host/config.json`：`canonicalOrigin`、`tenant`、`managementTenant`、`serviceId`。

`canonicalOrigin` 必须与浏览器 HTTPS origin 完全一致；业务、管理租户使用不同的非零 UUID。缺失或错误配置阻止启动。静态镜像自身不提供 API 或配置；不要直接用其 HTTP 地址进行产品登录。

网关保持 `script-src 'self'; style-src 'self'`。Ant Design 主题在构建时提取 CSS，运行时不放宽 inline script/style。SPA 深链接回到 index；不存在的静态资源返回 404，index 不缓存。

业务登录 `/login`，管理登录 `/platform/login`；OIDC 协议回调仅为 `/api/v1/identity/oidc/callback`，`/auth/resume` 只读取会话并恢复定位。公开入口 `/downloads/agent` 和 `/enrollment/windows/entra/terms` 不要求控制台登录。

## 当前操作入口

| 入口 | 归属与操作 |
|---|---|
| `/setup`、`/settings` | 服务端首次配置意图、显式跳过、实际领域配置与完成观察；完成不冻结后续健康 |
| `/authorization`、`/user-profiles`、`/identity` | 授权、资料映射、账户与 Provider；平台入口加 `/platform` 前缀，平台租户管理为 `/platform/tenants` |
| `/devices`、`/devices/:kind/:id` | 终端/关联身份、注册代次、资产、人员、操作、历史及领域导航 |
| `/enroll`、`/connections` | 注册、配额、通道和材料配置；安装 JSON 及秘密仅在当前任务内交付 |
| `/inventory`、`/groups`、`/compliance` | 服务端查询、固定结果、群组计算与合规历史；预览不发布正式结果 |
| `/resources`、`/software` | 六类资源固定版本、内容上传回执、来源导入、软件准入及 WinGet/Brew 源发布；设备分配在 Policy 维护 |
| `/scopes`、`/policies` | 范围定义/结果、精确资源绑定、自助发布、灰度与独立事件批次 |
| `/operations`、`/device-access` | 正式执行与原操作、用途绑定 DA 材料、账户绑定、因子和 Platform SSO 配置 |
| `/telemetry` | 来源、epoch、字段版本与维度绑定的历史/latest/聚合、健康和缺口 |
| `/certificates`、`/recovery-credentials` | 证书档案、设备 PKI、恢复元数据及有独立权限的精确披露 |
| `/audit`、`/webhooks` | 当前权限下的历史事实、订阅、投递观察与签名材料 |
| `/diagnostics` | 按 owner 拆分的运行诊断；正式合同缺口见下文 |

身份、会话、设备、注册或权限变化时清除相关结果和秘密，迟到响应不能覆盖新上下文。秘密不持久化；隐藏、关闭或离开清除。未知写入保留非秘密原身份和冻结输入，仅通过明确的原操作读取或用户确认后的相同请求恢复；刷新、重认证及冲突不会自动重放。

Resource 固定版本、内容上传与激活分别确认。上传续办读取原位置/回执并校验原内容；目录名称过滤只作用于当前页。Direct 软件材料不要求原生源发布；软件准入、源发布和实际设备安装各自独立。

## 真实 HTTPS 验证

各 runner 的后端变量必须指向选定 revision 的独立 rss-mdm 检出；管理旅程还需指定独立 rss-identity 检出。完整命令及各旅程范围见[仓库 README](../../README.md)。十一组入口是 `test:mdm:react-{auth,administration,devices-enrollment,assets,software,certificates,audit-webhooks,policy,execution-access,telemetry,setup}-browser`。

runner 复用后端构建租约、隔离 PG、PKI、HTTPS 宿主以及独立清理。进程有界，清理未确认返回失败并保留恢复目录。只输出无秘密摘要和公开页面截图，不记录秘密面板、原始网络正文或 trace。修复前先查看失败日志；重跑只选择失败与受影响范围。

实际镜像可复用认证入口，经同一 HTTPS 网关消费镜像内容：

```bash
MDM_REACT_BACKEND=/absolute/rss-mdm \
MDM_REACT_WEB_IMAGE=rss-mdm-web:my-version \
pnpm test:mdm:react-auth-browser
```

该模式由原认证 fixture 的 Compose owner 管理 web 容器及退出清理；其它业务旅程继续证明固定源码/正式 HTTP 接缝。镜像和业务结果分别记录，均不代替 Windows/macOS 真机效果。

终端目录/详情在正式候选的 503 由 #3142 跟踪；嵌入 DA HTTP 的授权顺序缺陷由 #3138 跟踪，RSS Login 恢复材料真实正向路径尚未验收，相关前端继续复用现有 HTTP mock/组件覆盖，不能把 MDM 与 DA 的设备/注册混作同一身份。配置 relay 运行角色错误仍由 #3137 跟踪。Agent 签名连接发布/管理员安装 JSON 的真实受控宿主前置由 #3144 跟踪，源码 fixture 不能伪造部署观察。

已登记后端缺口不阻塞本轮前端切换。新增缺口在排除前端或 fixture 问题后登记后端 issue，需要推进界面时复用显式 demo；生产不自动回退到 mock。交付记录分别列明真实通过、mock 覆盖、已知缺口以及真机未测范围。

## 部署切换与回退

构建并保留当前版本与上一版的前端镜像引用。先在隔离宿主验证新镜像与选定后端的组合，再由部署负责人设置 `MDM_WEB_IMAGE` 并按 rss-mdm 的[安装部署入口](https://dev.azure.com/shengming0923/rss/_git/rss-mdm?path=/docs/deployment/installation.md)更新 web 服务。验证业务/管理租户登录、公开入口、深链接和静态资源后完成切换。

旧页面及其 URL 不保留转发或兼容壳；原书签须改为上述当前入口。回退使用预先保留的前端镜像和已验证的后端/配置组合，更新 `MDM_WEB_IMAGE` 并重建 web 服务，再验证登录和关键读取。若同时回退后端或数据库，必须执行后端部署文档规定的成套恢复，不混跑不同候选。

本流程创建最终集成 PR，不自动合并最终 PR 或部署。历史来源记录保留在 `docs/migration`，不作为当前操作入口。
