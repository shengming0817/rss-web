# MDM 与 Identity 独立前端

`apps/mdm` 是 Windows/macOS 企业终端管理入口，`apps/identity` 是 Identity 宿主认证入口。两者独立装配、构建和部署，不共享跨域会话。`@rss/auth` 导出既有 cookie 会话、认证 UI、OIDC flow 与路由；每个应用只创建一个 controller。`@rss/core` 持有展示基础，`@rss/api` 持有唯一 HTTP executor。原 apps/web 已由 #2514 退出，不恢复旧 bearer 页面。

## 开发

```sh
pnpm install --frozen-lockfile
pnpm dev:mdm:demo
```

打开命令输出的 loopback 地址，使用纯合成账户 `demo / demo`。顶部始终显示 Mock，可按设备、策略、软件、安全、运营模块显式选择来源和场景，或重置并重新登录。场景包括 normal/empty/denied/forbidden/offline/unsupported/partial/conflict/unknown/late；各业务包负责其具体数据及操作分支。演示状态仅在当前开发服务内存中，重启丢弃。多标签页共用该演示状态，不代表生产会话隔离。策略与软件共享 Resource、Scope 和执行边界，切换任一模块来源会同步切换另一模块。real 来源未接入的能力返回不可用，不切回 mock。

演示使用 Vite 本地 HTTP middleware，不能构建为生产静态站点；`--mode demo` 的 build 显式拒绝。它不运行 MDM/Identity 后端，不证明设备注册、擦除、脚本效果或合规。普通 `pnpm dev:mdm` 不提供模拟 API；真实交互应使用 HTTPS 同源产品宿主。Identity 开发继续见[宿主认证 UI](20260917-2368-embedded-identity.md#交互开发)。

## 生产构建与镜像

```sh
pnpm build:identity
pnpm build:mdm
pnpm image:identity --tag rss-identity-web:VERSION
pnpm image:mdm --tag rss-mdm-web:VERSION
```

`pnpm build` 构建并扫描两个生产目录。Identity 产物不包含 MDM 路由，MDM 不包含 demo server、模拟身份或场景控制。镜像只复制对应应用的 dist，使用独立版本标签。构建使用当前工作树，允许未提交修改。类型/组件/API 验证采用现有 `pnpm typecheck/lint/format:check/test:coverage/test:boundary`，不需要源码快照、提交摘要或 consumer receipt。

两个应用分别拥有独立域名上的 `/`；不能在同一根路径同时部署两个 app。Nginx 配置与 TLS 材料由宿主注入 `/run/config`，前端镜像不持有秘密。

MDM 宿主需提供既有 Identity config/context 和嵌入 Identity HTTP V1，以及新增的静态 `/api/v1/mdm-host/config.json`：

```json
{"canonicalOrigin":"https://mdm.example.test","tenant":"11111111-1111-4111-8111-111111111111"}
```

origin 必须严格匹配 HTTPS 页面 origin，tenant 是宿主指定资源定位符；不生成租户 header，也不授予权限。示例 [`deploy/mdm/gateway.conf.example`](../../deploy/mdm/gateway.conf.example) 精确区分 config、Identity callback、业务 API 和 SPA。这是前端接入要求；rss-mdm 宿主新增配置、路由和实际生产部署仍待后端 owner 接入，不宣称已交付。

升级时记录两个现用前端镜像标签/ID，分别构建目标产品镜像，保留宿主配置、TLS 和后端数据卷，仅替换对应 gateway 镜像；验证 `/`、后端 `/livez`/`/readyz`、登录/退出、受控工作区与 API 错误；readiness 未通过不切流。失败时将该 gateway 恢复到先前镜像并重建容器，不回滚 Identity/MDM 数据库、不重放未知写操作。两个前端可以独立升级回滚；若后端合同发生破坏性变化，先按后端部署说明协调版本，不靠旧 wire fallback。

MDM 管理 HTTP 统一使用 `/api/v1/{资源}`，保留每个资源的当前语义与权限；旧管理版本入口退出，部署不进行路径重写。Identity transport 不扩大 allowlist。MDM transport 复用同一 executor，精确预期 200/201/202/204，闭合解码 Identity 认证错误与 MDM 产品错误。响应 request-id/Retry-After 目前未暴露给页面，不宣称已消费这些元数据。

缺失能力使用明确的 `/api/v1/mdm-candidate/` 候选命名空间，**不是已发布的后端 API**。后端 owner 为 rss-mdm；后续真实合同落地时调整 domain adapter 和交互。基础候选：

| 请求 | 响应/语义 | 权限、失败、版本 |
|---|---|---|
| `GET /api/v1/mdm-candidate/workspace` | `{modules:[{id,source,available}]}`；id 为 devices/policies/software/security/operations，source 为 real/mock，available 为 true/false/null | 有效会话；后端决定每资源权限；无分页/写入；null 为导航未知。生产拒绝 mock source。401 清会话，403 拒绝，503 不可用；不自动重试 |

业务 DTO 必须经 decoder。读响应绑定当前会话，失效或旋转后的迟到响应不再呈现。业务 403/409/503 与协议错误不清除有效认证；401 才通知 session owner。业务并发派发与凭据轮换由同一 owner 双向协调，写入在派发时取得当前 CSRF，不全局重试；Identity no-replay 与 MDM 每操作精确幂等合同分别处理，未知结果需要显式核实。

新增 feature 在 `apps/mdm/src/features.ts` 注册普通路由和入口，业务模块不再装配 session/transport。导航提示不代表授权；真实页面请求仍由服务端复核。候选请求/响应、分页/CAS/批准状态及异常覆盖随对应业务项维护，不能把未实现服务标成已接入。

共享包的 UI 与纯会话入口见 [`@rss/auth`](../../packages/auth/README.md)。网关须直接面对客户端，并由后端将该网关 peer 配置为可信来源；示例覆盖客户端转发头，仅转发实际 peer 地址，并沿用 rss-mdm 的登录/API 限流、连接数、默认正文 16 KiB 及 10 秒客户端读取预算。精确路径 `/api/v1/resources/{id}/content` 与 `/api/v1/resources/{id}/uploads/{upload}` 的网关正文上限为 16 MiB，承载原生 POST 内容上传和 PATCH 分片上传；`/complete` 及普通 JSON 路径仍为 16 KiB，授权 PUT 和证书存档导入的 2 MiB 精确路径例外见各模块说明。前端 transport 和服务端继续按方法及内容类型区分 JSON/二进制预算，上传仍受路径限流和读取超时约束；429 返回安全错误码与 Retry-After，前端不自动重放写入。诊断日志只含关联 ID、状态和时延，不含 URL、header 或 body。

## 设备控制台

从工作区进入设备目录，可查看包含首次 pending 注册的授权设备投影；资产搜索另用已发布的异步查询，不在浏览器合并资产和注册列表来推断完整授权集合。平台尚未采集时显示未知。目录统计、详情、注册与批量预览由同一个 HTTP demo 状态持有，重置同时清除查询、组任务、幂等回执和分页。

搜索提交返回任务 ID，使用“读取任务状态”显式刷新；完成后读取结果和 facets。查询与组结果分页只根据服务端 nextCursor 结束，允许空尾页；不按返回行数推断完成。字段状态 known/null/missing/unsupported/deleted/conflict、来源和 lastKnown 分别呈现，时间不产生资产 TTL。asset_states 聚合计算字段数，不代表设备数。离开页面只忽略迟到响应，不取消服务端任务。

Manual、个人查询、组定义及归属编辑使用当前 revision；冲突保留草稿，重读服务器值后由操作者比较并再次提交。未知写入不自动重试；明确重放复用原 operationId 和完整正文。组条件先保存，再预览已保存版本；只有重算发布成员，预览不修改成员集，规则解释由服务端提供。

注册通过 Web Crypto 生成 256-bit Base64URL 口令，操作者确认安全交付后提交；表单立即清除口令，页面不持久化口令或完整秘密请求。未知结果保留非秘密操作身份；精确重放必须重新输入原口令。create/resume/cancel 使用 Idempotency-Key、HTTP 200；撤销凭据的已发布 wire 回执是 `operation_id`/`registration`，与 enrollment 的 camelCase 不混用。授权期限是注册凭据的期限，不是资产期限。设备侧 profile 安装、APNs、Agent 安装 ACK 与有效注册/通道就绪不同；macOS password profile 下载通过原生密码入口取得签名二进制；TokenUpdate、系统安装确认和采集验收仍由设备侧事实提供。

ADE、Windows 自动化开通、入职、重新分配、丢失、退役、擦除及双通道引导均提供候选批量预览。冻结目标的设备版本、registration 和 generation，提交时重新复核；无权限、平台不支持、离线、旧世代、版本冲突逐设备列出。受理、下发、设备回执、实际效果和合规分别显示；demo 只受理模拟请求，效果与合规保持未知。详细执行记录由 #2546 配置与执行模块承接。

### 正式设备视图与关联（#2713）

设备目录消费 `/api/v1/device-views`，按服务端 reference、endpointCount/deviceViewCount、status/channel/source、descending 和不透明 cursor 分页；不从资产或候选列表拼接设备。旧 `/tenants/:tenant/devices/:device` 始终指向原端点，新 `/tenants/:tenant/device-views/:kind/:view` 表示 endpoint 或 association 视图。策略、合规和安全选择器消费 `/api/v1/devices`，保留原端点 ID。Manual 编辑、凭据撤销与业务链接也保留原端点身份。

| 请求 | 正式语义 |
|---|---|
| `GET /api/v1/devices?after&limit`、`GET /api/v1/devices/{id}` | 原端点、主注册、通道、声明式子注册、用户上下文、注册申请；详情附产品支持/设备前提/当前权限，不从安装 ACK 推断就绪 |
| `GET /api/v1/device-views?cursor&limit&descending&status&channel&source` | 已授权设备视图与服务端去重统计；仅一端授权时退化为独立端点，不暴露隐藏端点或关联 ID |
| `GET /api/v1/device-views/{kind}/{id}` | 服务端字段解析、按 endpoint/source/dataset 保留事实、冲突、lastKnown、质量与修订；两个 Manual 来源不在浏览器合并 |
| `GET /api/v1/device-views/{kind}/{id}/inventory-lists/{field}?cursor&limit` | 每个来源独立清单、完整性、证据与分页；回执须匹配视图、字段、原端点和完整来源证据 |
| `GET /api/v1/devices/{device}/association-candidates?channel&after&limit` | 另一主通道的当前注册候选；候选不是同实例证明，已占用端点不进入候选 |
| `GET /api/v1/device-associations/{id}` | 当前 confirmed/needs_verification/revoked 关系与版本；没有 operation GET 查询接口 |
| `POST /api/v1/device-associations` | `{operationId,associationId,expectedVersion,mdm,agent,evidence}`；create 使用 null/0，重新核实先读取当前关系和原端点主注册 |
| `POST /api/v1/device-associations/{id}/revoke` | `{operationId,expectedVersion,reason}`；解除关联不撤销注册凭据、不改变策略或组 |
| `GET /api/v1/devices/{id}/timeline` | 安全时间线事实与索引 coverage；不把审计成功解释成设备效果 |

写入需 `device_association_write`，当前身份对双方端点的有效授权由服务端复核。核实说明按 UTF-8 字节限制；操作者明确核对两端注册 ID/generation。409 要重新读取当前依据并再次核实；403/404 清除目标与配对事实。分页 409 `device_view_cursor_invalidated` 清除当前页及视图，必须显式重读，不能接续旧页。

未知写入保留原 operationId、正文与身份绑定，仅保存在应用运行期内存；SPA 导航后返回可恢复，切换会话或身份清除。只有操作者明确确认后才能幂等 POST 重放完整原请求；普通 GET 现状不确认为该操作回执，不自动重试，也不新建 operation。浏览器关闭或整页重新加载不持久化请求。

通道卡明确区分注册事实与 Inventory 证据。当前后端没有“最近通信”字段，缺口由 rss-mdm #2717 承接，生产显示暂未提供；Inventory receivedAt 仅显示当前注册代次的采集接收时间。demo 显式标注合成通信事实，不能证明在线或真实签到。前端采用当前 `assets-v2` 字典及完整 Scalar/来源/list 读取合同，旧 DTO 不再解析。

## 配置、持续分配与执行控制台

策略模块提供 Scope、资源/内容上传、平台配置目录、持续分配、脚本入口、多步工作流、执行中心与显式工作流审批。普通脚本在资源库编辑参数和输出 Schema，再引用资源版本创建持续分配；没有独立 ScriptPlan 或普通脚本第二主体审批。策略页一次 CAS 保存来源、版本、动态 Scope、触发/频率、启停、退出行为和可选 UTC 有效窗口。Scope 成员为空时可以保存；可选预览不保存策略或创建运行。

后台成员计算序号与配置 revision 独立。“刷新进度”保留编辑草稿，“重新载入配置”明确替换草稿；409 后先比较最新配置再提交。未知写入只能显式重放原 operationId 与完整请求；Unknown 执行效果不会自动重发。取消在途运行不代表撤销已生效配置，取消请求/确认、受理/派发/回执/执行/效果/合规分别展示。既有执行记录保留，资源换版或设备身份变化不改写旧结果。

DemoControls 写入沿用应用唯一会话的登录/CSRF 校验，可注入 UTC 时间、设备注册或签到事件；事件只推进 HTTP demo 服务端，页面不持有调度器。设备注册写入和设备组任务发布后自动解析动态 Scope；时间与签到由模拟事件驱动。真实模式不启动该 owner，也不在真实失败后降级。演示重置会清除全部策略、运行、工作流、上传与分页状态；它不证明生产重启持久化恢复。

事件时间留空时，控件在每次提交前读取服务端场景 `asOf` 并加一秒；手填 Unix 秒用于推进时间或测试迟到证据。合规评估、保存、重算及审计共用安全场景时钟。远程同意和撤销填写申请 ID，其余支持观测填写原执行任务 ID；目标不存在、时间或状态不允许转换的同意/撤销事件返回 409，控件保留输入并显示未确认提示。事件显式推进的场景时间不会倒退；失败不代表其他观测或授权期限已回滚。

### 正式 Policy 与自助访问配置

脚本策略、持续配置和软件部署共享 `/api/v1/policies` 的正式模型与配置 owner。读取为 `{id,revision,version,versionId,state,definition}`；definition 为 `{scope,action,selfService?}`，action 使用 execution/native_collection/agent_collection/configuration/software/ensure_agent_installed/request_mdm_enrollment 闭合分支。删除 candidate assignments、computation、members、archive/cancel_run 与 candidate preview，不做双重解码。

持续配置在 Policy 页选择 configuration，加载已激活 Resource 的精确平台/架构/变体，并选择 retain/remove；移除能力由不可变原生 artifact 定义。Resource 配置 declaration 只持有 artifact，原生 target/apply/remove 位于上传内容；不再提供旧 firewall_version 快捷字段。配置目录的候选预检消费有效原生 claim；保存、操作 ID 和 mock 规划不证明设备效果，漂移与实际效果保持 unknown。

| 正式请求 | 语义 |
| --- | --- |
| `GET /api/v1/policies?cursor&action&limit` | `{items,nextCursor}`；不透明 cursor 分页；脚本页筛选 execution，软件页筛选 software |
| `GET /api/v1/policies/{id}` | 当前配置；不是写入回执或执行结果 |
| `POST /api/v1/policies/{id}` | `Operation<{action:"put",definition,enabled}>` 或 enable/disable；operationId 与 expectedRevision CAS；200 正式 Policy |

execution 固定 Resource 的 id/version/platform/architecture/variant，Resource 唯一持有参数 Schema、字段类型和约束。Policy 仅保存每字段 fixed/value 或 input，动态参数要求 manual schedule，不复制 Schema。页面需先加载精确的已激活脚本变体，再编辑固定值或允许的输入来源；服务端复核权限、Resource、Scope 和资格。

selfService 保存必填 access、published、displayName、description、prerequisites、sideEffects、category、keywords、allowAi 与 riskLevel。access 为 device、authenticated_user 或 users；users 持有用户三坐标、固定来源的 IdP 群组、部门 exact/subtree 或静态 user_group，按 OR 求值，与设备 Scope、执行 schedule、管理授权及 Resource runAs 独立。旧定义由后端迁移为 access=null、published=false；页面要求显式选择再发布，不推断权限。脚本第一次打开发布默认 allowAi=true、riskLevel=2；已有 false/1 保持原值。软件仅 available_install 支持自助配置，风险固定为 2，页面不提供 AI/风险编辑项。riskLevel 只允许 1/2。保存配置、发布/撤回、关闭 AI、禁用整个 Policy 分别处理；发布不创建任务，撤回不抹除历史，关闭 AI 保留人工自助，禁用整个 Policy 保留已发生的效果与证据。元数据、Scope 和启停只增加配置 revision；执行 action 改变才产生执行版本，software rollout 同样不改变执行版本。

写结果 Unknown 后保留 operationId 并禁止后续写入；读取当前配置不确认原操作回执，不自动重放。员工目录、调用和结果已由 rss-mdm 的 Agent runtime 契约持有，始终要求设备凭据；device 访问无需员工会话，authenticated_user/users 要求受信任员工会话，由 Agent 消费；管理浏览器仅通过正式 Policy/Resource API 配置，不代员工执行或确认。Unknown 时可显式核对／重试完整原请求，同一身份、目标、operationId、revision 和正文经服务端幂等受理；此前未受理时会提交原操作。确认后重读当前配置再开放写入，读取配置本身不确认回执。

显式 loopback HTTP demo 使用同一份 Policy store、CAS 与回执，不保留第二份发布目录。启动及重置经相同 HTTP owner 写入四条演示策略：发布且允许 AI（风险 2）、发布且仅人工（false/1）、已撤回、已禁用；均引用真实的合成 Resource/Scope 数据。输出只标记合成，不声称真实 Agent 执行。生产构建排除 demo 模块，生产请求不回退 mock。

## 原生合规规则与评估证据

安全模块的合规规则与设备结论使用 rss-mdm #2469 的当前 `/api/v1` 合同，不加候选 envelope。后端拥有判定、平台注册来源、群组成员与事实新鲜度；页面不重新计算合规。无启用规则为 `unknown/no_rules`；`unknown`、`not_applicable`、`pending` 都不显示为合规。等待重评时 `current:null`，`previous` 单独标为上一轮证据；历史记录保持当时规则版本、任务 disposition、事实水位、字典版本、评估时间及来源引用。

| 路径（前缀 `/api/v1`） | 当前合同与权限 |
|---|---|
| `GET /compliance-rules?after` | `ComplianceRuleRead`；固定 50 条、按 UUID 的 after 分页；`{items,nextCursor}`。与历史 cursor 不互换 |
| `GET /compliance-rules/{id}`、`.../versions/{revision}` | `ComplianceRuleRead`；`{id,revision,definition}`，指定版本不可变。definition 为 name/severity/enabled/platform/target/criteria；target 为 all 或 1–16 个唯一群组；Criteria 非 null |
| `PUT /compliance-rules/{id}` | `ComplianceWrite`；`Operation<definition>`、revision CAS；200 `{id,revision,task}`，enabled 时 task 非 null；停用保留历史 |
| `POST /compliance-rules/{id}/recompute` | `ComplianceRecompute`；`Operation<{}>`，当前 revision 且启用；200 `{task}` |
| `GET /compliance-rules/{id}/tasks/{task}` | `ComplianceRuleRead` 及全设备 `ComplianceRead`；规则/版本/事实水位、phase、processed、completed、failure、diagnostic 分开呈现；queued/evaluating/published/superseded/failed |
| `GET /devices/{device}/compliance` | 当前设备 `ComplianceRead`；`{device,status,reason,rules}`，每规则保留 current/previous，不用历史替代当前结论 |
| `GET /devices/{device}/compliance/history?from&until&limit&cursor` | 当前设备 `ComplianceRead`；UTC 秒闭区间、limit 1–100（默认 50），不透明 cursor 绑定租户/主体/设备/时间范围；`{items,nextCursor}`，items 额外包含 task/disposition |

401 交给唯一会话 owner，403 拒绝访问，400 为无效请求，404 为不存在，409 为冲突，503 为不可用或结果未知。写入未知保留原目标、operationId、expectedRevision 和完整非秘密正文，只提供显式原操作重放；普通 GET 不解除未知锁定。修订冲突由操作者读取最新规则后重新编辑。敏感事实不放入合规证据；这里只展示来源、注册代次、epoch、快照、观测/接收时间、条件路径与结果。

Mock 初始没有合规规则。在安全模块新建规则、选择条件或显式空 AND 条件组，保存后读取任务两次推进合成评估。空静态群组可就绪且不匹配；动态群组须发布与当前规则/事实对应的成员集。事实或群组输入变化使当前结论待评估，可显式重新评估；未就绪冻结输入以 `superseded/group_input_pending` 结束。Mock 不实现生产 dispatcher 或设备采集；任务、证据与分页只验证前端合同和状态流，真实联调与产品验收仍待完成。

## 合规基线与例外候选

基线固定已发布 Scope 的 revision、原始设备成员与来源，以及每条原生规则的不可变版本。每次保存明确重新固定 Scope；后续范围变化或输入未就绪显示漂移，不静默替换目标。宽限使用绝对 UTC 截止时间，最多设置到当前服务器时间的 30 天后，改名不重置宽限。停用基线保留原生证据。

|---|---|---|
| `GET /baselines?limit&cursor`、`GET /baselines/{id}` | security.baseline.read，后端过滤资源 | 分页 `{items,snapshot,nextCursor,asOf}`，详情 `{baseline,asOf}`；baseline 含 id/revision/operation/createdAt/scopeRevision/definition |

| `GET /baselines/{id}/devices?revision&limit&cursor` | security.baseline.read 及设备 compliance.read | `{baseline,revision,items,snapshot,nextCursor,asOf}`；版本不匹配 409；每设备包含原始 native 结论和每固定规则的 nativeStatus/drift/governance/request |

## 风险与整改候选

风险页呈现提供方、来源版本/发布时间、严重度、修复优先级、软件标识、受影响版本及修复版本。每设备评估独立保留评估 ID/版本/时间、affected/clear/unknown/not_applicable、原因、软件观测版本、补丁可用性以及证据来源注册代次。空列表、清单中存在软件、审批通过或设备命令成功均不等于风险消除；clear 只对应有来源证据的本次评估。历史评估不可变。Mock 使用明确的 `DEMO-RISK-2026-001` 和合成提供方，没有虚构真实 CVE。

| 候选路径（前缀 `/api/v1/mdm-candidate/security`） | 请求 / 权限 | 响应与一致性 |
|---|---|---|
| `GET /risks?limit&cursor`、`GET /risks/{id}` | security.risk.read | 既有 security-v1 分页或 `{risk,asOf}`；risk 保留 provider、revision、publishedAt、software 与独立 severity/priority |

| `POST /risks/{id}/devices/{device}/reassess` | security.risk.assess；`Operation<{}>`，expectedRevision 为当前评估 version | 200 `{assessment,operation,asOf}`，新评估 version+1；读取当前来源输入重新评估，历史不改写；未知提交只显式原操作重放 |

## 软件来源、Resource、导入与发布

本次正式合同固定 rss-mdm `5638705a408c5ac06d54bf166182e3822eb9c903`（PR #1330）。浏览器入口与覆盖边界见 README 的 `test:mdm:software-browser`。

软件目录直接读取 `GET /api/v1/resources?kind=software&after&limit` 的 Resource 头，选择后单独读取详情和不可变版本。目录没有独立名称、许可、使用率或替代关系模型；当前页不是全局搜索结果。来源修订、实际发布目标和发布记录分别使用 `/api/v1/software/sources`、`/api/v1/software/publication-targets` 与 `/api/v1/software/publications` 的 after 分页目录，默认 20、最大 100；资源仍复用现有目录。

企业来源使用 `/api/v1/software/sources/{id}/revisions/{revision}`。definition 包含 id、固定 revision 与 protocol，支持 private、winget_rest、winget_community、brew_tap；公共 HTTPS 地址无凭据，仓库来源固定 commit。register 直接启用；enable/disable 使用当前 lifecycle.revision 做 CAS。版本使用 `/api/v1/software/resources/{id}/versions/{version}` 的 enable/withdraw，草稿 lifecycle 为 null。来源停用和版本撤回阻止后续安装，不自动卸载；软件 Policy 的运行准入由后端持有，作者不提交 admissionOperation 或审批 evidence。

Resource 是包定义、内容、版本和依赖的唯一 owner。声明为 `{kind:"software",definition:SoftwareSpec}`，包含 source/package/version、provenance、artifacts、behavior、signatures、reboot、downgrade、dependencies 与 export。安装身份来自 invocation。Resource 写入和 Policy 定义预算为 8 MiB，普通请求 16 KiB；流式内容由上传 owner 持有。上传仍使用 Resource uploads 的固定 binding、offset、分块 PATCH 和显式 complete；中断恢复须重新读取同一上传会话，不自动重放写入。

精确导入直接 `POST /api/v1/software/imports`，请求固定来源快照、包/平台/架构、selection、安装行为、材料长度及辅助 artifacts/dependencies/signatures。200 同步返回 resource、version、resourceDigest、storageRevision；没有 resolution、异步 job、cancel 或 reconcile 协议。导入不启用版本。Unknown 后只读取资源供核对，读取现状不能证明原操作完成，也不会自动重发。

外部发布直接 `POST /api/v1/software/publications`，输入确切 resource/version、expectedResourceRevision、resourceDigest，以及实际 target/targetDigest；服务端派生文档并原子受理，202 表示已受理。单个目标即可工作。详情及 Recover/Retry/Withdraw 使用 `/{id}`；内部 publication/attempt 由服务端读取。仅明确 not_applied 才重试，Unknown 查询原 operation 后需明确确认才能重放同一正文。撤回禁止新的消费并恢复源下架，不自动卸载设备。Direct 安装不依赖任何发布目标。Native 部署选择该确切版本的已发布目标，所有设备批次共用同一版本和目标。

设备部署默认“全量”，内部只创建一个使用 Policy 总 Scope 的阶段；选择“分批”后才显示阶段 Scope、UTC 开放时间和可选上一批成功率门槛。成员受总 Scope 限制，重叠设备归最早阶段。无门槛时按时间自动开放；有门槛时统计未就绪、样本为空或比例不足均等待，Unknown 与待重启不算成功。暂停阻止后续准入，不自动回滚已有安装。界面展示等待时间、等待统计、门槛未达和执行结果。

软件更新复用现有部署编辑、预览与提交，显式选择新版本；发布 v2 不暗改 v1 策略，自助安装不变为强制更新。未增加 latest 追踪、版本监控或独立补丁平台。

HTTP demo 与生产共用客户端、DTO 和端点。有限合成上游只支持固定 Example.Browser/128.0 和 example-editor/1.0；不支持的输入材料明确返回 unavailable/unsupported，不静默丢弃字段。演示发布使用实际目标 demo-winget 与 demo-brew，支持 WinGet 与 Brew Cask 文档；不支持的导出形式明确 501。没有正式 Agent 发行包，公开目录为空；演示不证明真实源、签名、安装、发布或设备效果。

## 设备证书候选

`security-v1` 证书记录绑定 device 与 profile（id/name/platform/protocol/issuer/purpose），严格区分 issuance 与 installed。仅消费公开元数据 serial/fingerprint/subject/notBefore/notAfter；不接收或展示私钥、CA 密码、CSR 或下发内容。当前合成 profile 为 Windows SCEP / macOS ACME 设备身份用途，协议执行不在前端交付内。

| 候选路径（前缀 `/api/v1/mdm-candidate/security`） | 权限 / 一致性 | 响应与异步语义 |
| --- | --- | --- |
| `GET /certificates?device&limit&cursor`、`GET /certificates/{id}` | security.certificate.read，按设备资源过滤；分页绑定主体/筛选并冻结 asOf | security-v1 分页或 `{certificate,asOf}`；必填 id/revision/device/profile/source/issuance/installed/validity/evaluatedAt |
| `POST /certificates/{id}/issue` | security.certificate.issue；Operation 空 input、CAS、精确回执 | 请求签发或续期，issuance `{operation,state,requestedAt,resultAt,credential}`；state requested/issued/failed/unknown；受理不产生证书，未知占用原尝试 |
| `POST /requests` 与审批路径 | security.certificate.deploy.request/review；申请者与审批者分离 | `certificate_deploy {device,certificate,certificateRevision,fingerprint}` 固定已签发证书和记录版本；无效、过期、错指纹或来源不可执行时拒绝 |
| `POST /requests/{id}/dispatch`、`GET /actions[/id]` | 既有安全执行权限，批准有效期/主体/目标与设备注册能力再次校验 | 单一 action/execution owner，冻结 mdm.windows/mdm.apple 注册代次及 certificate.deploy.v1 能力；受理、结果和安装观测分别展示 |

安装观测包含 credential/observedAt/source。服务端根据有效期和当前注册来源报告 unknown/not_yet_valid/valid/expiring/expired；来源变化保留历史证书元数据但当前有效性变成 unknown。Mock 提前七天告警，首次合成设备证书一小时后到期，其他设备初始无安装观测；缺失不能推断已保护。到期状态随服务端时钟推进，唯一运营 owner 持有 certificate_expiry 告警，确认不会解除告警。

演示先对签发 operation ID 注入 `certificate_issued`（支持失败、未知及同尝试后续结果），再单独申请/批准/派发部署。`security_result` 只表示命令结果；之后对原执行 ID 注入较晚、同设备/注册代次的 `certificate_detect`，才更新 installed。新证书签发和命令成功都保留旧证书及其到期告警；新设备观测证明有效证书已安装才解除。旧指纹、过期候选、乱序和旧注册证据均不能证明替换成功。

写入使用既有非秘密精确回放：未知结果保留原正文，GET 不解除未知锁，成功回执后再读当前状态。400 无效正文、403 无权、404 不存在、409 版本/生命周期冲突、501 无能力、503 不可用或提交未知；已知失败可在读取当前版本后发起新签发，未知签发必须等待原结果。审计仅记录证书/设备/版本/操作引用和结果，不保存申请理由或凭据正文。真实证书服务与设备效果仍由 rss-mdm 和设备侧验收。


## 终端支持与体验候选

支持流程继续使用同一 `security-v1`、请求审批 owner 和安全 action/execution owner。浏览器不拥有 OS 权限判断或远程用户同意，也不接受任意脚本、命令和诊断路径。目标能力来自服务端设备 context 的平台、Agent 注册代次和独立 capability；设备数据可读不代表可执行支持操作。

| 候选路径（前缀 `/api/v1/mdm-candidate/security`） | 权限与闭合输入 | 响应 / 状态 |
| --- | --- | --- |
| `GET /support/devices/{device}` | security.support.read，资源授权 | `{context,asOf}`；context 包含 device/revision/platform/source/capabilities/accounts/programs/evaluatedAt；program 为 id/name/path/sha256/publisher，能力为 elevation/diagnostics/remoteModes |
| `POST /requests` 与独立 approve/deny/revoke | security.support.request/review；Operation/CAS，申请者不能自批；窗口最多一小时 | elevation target 固定 device/contextRevision/account/完整 program 身份；diagnostics 固定 artifacts 与 retentionSeconds（最多七天）；remote_support 固定 device/contextRevision/mode(view/control)；requester 从会话推导，远程 request ID 即唯一 attempt |
| `GET /support/requests/{id}` | security.support.read，关联设备权限 | `{support,asOf}`；support 为 request/requester/target/source/action/details；action 仅引用已有执行 ID，details 分别为授权与用户运行、诊断材料、用户同意与会话观测 |
| `POST /requests/{id}/dispatch` | security.support.dispatch，当前主体必须为申请人；重新校验批准/窗口/目标/注册/能力；远程必须有本次设备用户同意 | 既有安全 action 的精确非秘密回执；一项申请最多一个 action，失败重试需新申请；未知尝试保持占用，普通 GET 不解除写入未知锁 |
| `GET /support/devices/{device}/experience` | security.experience.read，资源授权 | `{experience,asOf}`；device/window(from,until)/source(provider,registration)/evaluatedAt/metrics；每项显式 value/state/sampleCount/denominator/unknownCount |

提权只针对 context 中观察到的账户和精确程序 SHA-256/路径/发布者元数据。批准和命令结果不等于设备已授权；独立 `support_detect` 才记录 grant.available。`elevation_used`/`elevation_ended` 分别表示设备观察到用户运行/进程结束。申请过期或撤销阻止新使用；未确认的授权撤回与正在运行进程均为 unknown。`elevation_revoked` 只证明设备撤销 grant，仍不证明旧进程结束。支持状态记录观测事实，唯一 action 持有 ExecutionSummary；当前不确定性及撤回确认更新该摘要，页面不另存执行生命周期。

远程协助为 attended view/control。独立审批后，设备侧合成 `remote_consent`（task 为 request ID、active 为接受/拒绝）绑定原申请的 helper/requester、device、mode、attempt 和注册来源。同意最多五分钟且不超过申请窗口；管理员没有同意 HTTP API。未同意、拒绝、过期、撤销或旧来源均不能派发。重试新申请不会继承旧同意；已有会话期间也不能另起同目标会话。命令成功后仍须独立设备 `support_detect` 才表示 connected。`remote_revoke` 使尚未结束的会话变成 unknown，`remote_ended` 才确认 ended；无屏幕、按键、录制、连接凭据或 launch token URL。

诊断只允许 system_events/inventory_summary/network_summary 三类摘要。`support_detect` 记录采集时间和合成 records/bytes 元数据，之后 `diagnostic_uploaded` 与 `diagnostic_scanned` 分别确认上传和扫描；乱序不能跳阶段，扫描支持 clean/blocked/unknown，保留期从采集时间计算，到期不再显示 ready。本前端只展示合成摘要，不提供真实 archive 下载或内容传输。

上述支持事件除 consent/revoke 使用申请 ID 外，都使用唯一 action ID，同时核对 device、当前注册来源和时间顺序。演示控制器是开发/演示入口，不是产品设备事件 API。元数据审计复用 operations owner，保存主体/动作/对象/操作/结果，排除理由、诊断原文、程序输出和会话内容。已知错误复核当前版本后可重新申请；未知写只显式重放原 Operation。400/403/404/409/501/503 与既有候选错误语义一致，真实接口失败不会回退 mock。

体验数据来自独立合成 telemetry provider，不从安装清单或当前磁盘字段推出趋势。boot_seconds_p95 单位秒、分母为预期启动事件；crashes_per_100_sessions 是每百次有效应用会话的崩溃数、分母为预期应用会话；disk_free_percent 为磁盘空闲百分比均值、分母为预期磁盘采样。服务端明确 complete/incomplete/unknown；缺失覆盖不补零，没有可验证来源时值和未知分母为 null。窗口固定于模拟提供方观测，读取不会生成更新的样本；来源变化会使当前证据 unknown。页面直接展示来源值与口径，无浏览器聚合或真实遥测引擎。

设备详情提供合规、材料、证书、支持、体验及安全执行/申请和运营审计/告警的双向入口。原生合规问题可进入既有配置、Scope 和执行流程；修复效果仍需新设备证据和显式原生重评，不因页面导航或命令成功改变结论。安全整改与远程支持组合测试使用生产 domain clients 经模拟 HTTP 边界消费 DTO，并验证切换 security 或 operations 为 real 后，相关 native security、security candidate、共享 executions 和运营投影统一拒绝读取模拟结果。当前仅完成前端交互与 HTTP mock 验证，未运行真实 MDM/Agent/CA/保管库/遥测验收。

### 当前授权 v1

`GET /api/v1/authorization` 返回实例/租户/主体及后端计算的有效 grants；规则和用户组列表使用 `after=UUID`，每页最多 100，不提供冻结快照。用户组列表返回 memberCount；完整成员分页使用 `offset`/`expectedRevision`。组编辑先读取同 revision 的全部成员，再整体 PUT，不能用当前页覆盖整组。

规则/组 PUT 使用 `{operationId,expectedRevision,value}`，新建 revision=0，删除 value=null，200 返回 `{id,revision,deleted}`。UUID tombstone 不复用。重放也须重新授权；Unknown 只允许显式原操作/原正文重放，409 保留草稿并比较服务器版本。可能移除管理访问的变更须先确认职责交接；没有内建防锁死或自动恢复授权。

客户端、demo ingress 与网关示例只为 `/api/v1/authorization/{rules|user-groups}/{uuid}` PUT 支持 2 MiB JSON；证书存档导入 POST 的独立例外见下文，其余 JSON 仍为 16 KiB，内容上传沿用既有 16 MiB。部署现有网关时需同步此精确路径预算。

### #2548 修复后的协议与事实约束

候选批量设备操作在 HTTP mock 组合根读取现有批次 owner 的事实，并在 preview、execute、cancel、read 和精确回执重放前重新检查当前授权。wipe 使用逐设备 `device_wipe`，reassign 使用逐设备 `inventory_assign`，cancel 使用逐设备 `operation_cancel`；尚无真实动作映射的其它候选生命周期动作明确使用 Mock 管理决策 `authorization_write`。所有目标另需 `inventory_read`，任一目标不满足则整次请求拒绝；不新增真实 Permission，也不把历史 preview 当作授权凭据。

管理写入回执绑定 operationId、目标 ID、CAS 后继 revision；新报表、维护任务和投递的 ID 为 operationId、初始 revision 为 1，投递另绑定 connector。精确重放仍返回原始提交回执，页面随后读取当前事实。报表完成审计保持 `report` 对象类型。

投影积压和 Agent 健康告警复用诊断事实；普通场景的 Agent 健康 unknown 不推断为 healthy 或告警解除。连接器停用状态优先于异步投递健康，投递历史独立保留，重新启用时恢复最后一次业务投递的已知事实。最后一次业务完成由投递 owner 在显式 tick 中按观察顺序记录 delivery ID；同时间戳也按该顺序，独立投递链的 attempt 不参与新旧排序。该索引只引用现有投递事实，reset 时清除，不另存健康缓存。表单允许清空公开引用并提交 null，协议解码仍拒绝空字符串。连接器 query id 变化清除旧目标、草稿、投递和待核实回执；迟到响应由现有 useOperation 拦截。

## 证书存档（#2641，真实 API）

安全管理的证书存档页面消费 rss-mdm `/api/v1/certificate-archive`，使用现有登录会话与共享 HTTP 执行器。租户路径只定位资源；后端核验 `certificate_archive_read/write/unlock/export` 的 Tenant scope 权限。页面支持导入、生成 CA/私有 HTTPS/CSR/APNs CSR/SCEP 前置模板、完整版本与手工导出，到期信息可在锁定状态读取。

导入最多 16 个文件、原始材料合计 1 MiB；Base64 JSON 正文预算为 2 MiB。部署时须同步网关精确路径 `/api/v1/certificate-archive/import` 的 POST 例外（`client_max_body_size 2m`），其余存档路径仍为 16 KiB；限流、读取超时和禁止自动写入重放继续适用。

主密码、文件密码和导出材料只保留在当前组件内，提交后清理输入；切换会话、离开页面、锁定、换主密码或解锁到期会清除暂存文件及文件密码并释放下载 URL。初始化、换密码及其他持久写入使用 `Idempotency-Key`；结果未知时只查询原操作，不自动重放秘密。主密码的持久保护、数据库恢复与全项目证书用途以 rss-mdm `crates/certificate-archive-service/README.md` 为准。该页面不属于 security-v1 候选合同，没有 mock 回退，不替其他服务装载证书或实现设备 PKI。

## 自助注册与注册归属

已登录租户用户可从应用导航打开“注册我的设备”，入口不依赖设备管理模块可用提示。自助网页只创建 Windows MDM／macOS MDM 原生注册，Agent 网页 grant／取消／activation 入口及其客户端已退出；Agent 仍由安装器消费管理员 JSON。页面分别展示 Agent、Windows MDM、macOS MDM 的有效额度、已注册和待完成占用。额度不足显示注册额度提示；密码在提交、导航或会话变化时清除，未知结果保留原操作身份以便用户核对后精确重放。

管理员“注册额度”使用注册服务的租户默认值、用户覆盖和版本写入契约，用户覆盖留空继承默认。组织设备“注册用户／设备责任人”独立于既有资产使用人字段，可通过设备详情入口设置、修改和留空；始终不占个人额度，也不授予设备权限。用户选择复用当前 Identity 会话和账号列表权限。三个页面均由服务端执行权限与租户隔离检查，Demo 只模拟这些接口，不代表真实注册或设备执行。


## 原生注册、组织接入与 Agent 安装交付（#2633）

注册通道与个人额度分别读取。`GET /api/v1/registration-channels` 对有效用户开放，现有“注册额度”页面同时展示三通道运行准备状态、故障原因及 allowed/paused；仅 `registration_configuration_write` 可通过带稳定 Idempotency-Key 和 expectedRevision 的 PUT 修改准入。普通用户可读通道，不因此取得额度设置或管理员配置权限。前端共享投影绑定租户、主体和会话，身份变化立即清空；失败读取不沿用允许注册的旧结论。

暂停只限制新注册与未完成首次激活，保留查询、取消、撤销、组织配置修复、既有设备及匿名下载。员工新建还须满足服务端个人额度，管理员指定设备注册不套用个人额度。旧页面收到 enrollment_paused / registration_limit 后刷新通道及相关额度，不自动重新提交。通道设置 Unknown 保留原命令，GET 只展示当前状态；显式重试使用原 operationId、revision 和目标值取得幂等回执，再刷新当前事实。冲突须读取并确认新依据后才发起新意图。

`/downloads/agent` 无需登录，消费 Agent HTTPS listener 上已正式发布的 `/api/v1/agent/enroll/packages`、`/{releaseId}` 与 `/{releaseId}/content`。用户明确选择 Windows/macOS、x86_64/aarch64、test/pilot/production，页面显示文件名、大小及安装器摘要；使用浏览器直接下载真实 NSIS EXE/PKG；目录中其他合法格式明确显示本入口不支持，不提供下载按钮。空目录明确显示无可用安装器。公开目录不持有注册额度、grant、设备或私有 Resource 读取能力；signingKeys 是配置验证用途，不能作为 Windows Authenticode／Apple notarization 的证明。

部署必须同步 gateway 示例的精确三路径代理：独立 Agent listener 使用 HTTPS、CA 验证和明确 SNI／Host；`proxy_pass_request_headers off` 后只重建 Host、Accept、Range 与条件下载头，不转发 Cookie、Authorization、Identity/CSRF 或设备 peer 头。将 agent.example.test:8447、上游地址及 agent-ca.pem 替换为实际配置，不将整个 Agent 路由族暴露到浏览器。公开安装器和管理 JSON 两种交付不混用。

具备 agent_enrollment_read/write 的管理员可打开 `/tenants/{tenant}/agent-configurations`。页面消费后端 settings 的默认期限、最大31536000秒与固定文件名 `rss-agent-enrollment.json`，选择有限正数或无限制以及目标/渠道。创建交付包含 configuration、secret、signature 的完整 UTF-8 JSON 原字节，不重新序列化签名文件；文件仅在显式下载中短时存在，导航、会话、权限变化或页面隐藏会释放 Blob URL。将 JSON 放在安装器同一目录；不得向浏览器上传文件或通过 URL 传递秘密。设备侧消费与可信安装仍由 #2634／#2632 持有。普通用户不显示管理员入口及期限表单。

管理写入未知时只查询原 configuration operation。null 继续表示 Unknown；已找到的 active 配置须确认撤销后才能重新生成，不恢复秘密、不重放创建。剩余数量来自后端 remaining，unlimited 为 null，过期与撤销独立呈现；settings CAS 未知只重新读取当前版本并由操作者确认下一次写入依据。当前已注册 Agent、agent.builtin 来源、注册记录、额度、凭据撤销和软件执行能力不因网页入口退出而删除。

原生 enrollment GET 严格读取 instructions/progress；create/resume/cancel 回执保持提交时快照，回执不冒充当前状态。Windows 页面提供系统设置、discovery、UPN、Full/Device 及本地管理员前提。macOS 口令下载使用原始 transport 的 password profile POST，凭据401不清除 RSS 会话，二进制签名 mobileconfig 保存后由系统安装。profile准备、证书、首次设备联系、系统确认、管理就绪及诊断分别显示，不从下载或按钮点击推断成功。

Apple 账户驱动注册和 ADE 为独立组织配置，消费正式 Apple organization API，authorization_read/write 由服务端裁定。MAA 配置组织域、宿主签名用途和当前 Identity 实例的 canonical 账户映射；浏览器只整页导航到已有 authenticate bridge，不复制或嵌入 bridge.js。ADE 配置 server UUID/org ID，导出公开证书、导入加密 p7m token、分页同步设备、维护 Setup Assistant profile 并分配。token 在提交、会话/权限变化及离开页面时清除；unknown assignment/profile 只显式 reconcile/resolve 原操作。ABM/ASM 数据、token验证或分配始终不蕴含注册。

Entra 页面配置明确用户 scope、background authority、termsVersion 和最多32768 UTF-8字节的纯文本 termsText；正文变更必须更新条款版本。PUT 精确128 KiB正文预算，与其它 JSON 默认16 KiB分离；ADE 普通 JSON 仍为16 KiB。匿名 `/enrollment/windows/entra/terms` 仅从正式 context 取条款和短期CSRF，通过原生 form POST finish 继续；JWT和OpaqueBlob始终由后端持有，组织join不显示拒绝，过期后禁用决定。gateway只为这一页面允许明确配置的原生frame origin，其它页面保持 frame-ancestors none。原生start/callback、Entra provider/native_callbacks和旧安装重装要求见 rss-mdm Windows指南。

Demo 通过显式合成HTTP owner提供组织/配置/条款合同，生产不导入或回退它。Demo没有正式签名安装器，公开目录为空，profile/public-key未模拟真实签名材料时明确不可用；模拟token和操作结果不证明Apple/Entra/设备效果。

真实 HTTPS 浏览器复用同一入口，可消费已有宿主，也可自动创建隔离环境：

## 控制台导航与任务工作区

MDM 使用独立控制台布局，Identity 继续独立部署；两者共享认证 UI 与会话生命周期，不共享产品导航。
桌面侧栏按设备、策略、软件、安全和组织运营组织入口，窄屏从顶栏打开导航。Ctrl/Cmd+K 搜索页面入口；资产内容搜索仍在设备模块内使用授权查询。

对象目录与新建、编辑任务分开。详情视图和向导步骤使用页面本地状态，切换视图不改变路由、不重建写入操作。软件选择器读取当前授权目录，选择后仍须执行版本、变体与准入验证；手工准确标识输入保留用于未列在当前分页中的对象。目录分页与已加载条目筛选均不代表全量目标选择。

工作台分别读取授权设备统计、待审批工作流、部署配置和审计事件。服务端拒绝或不可用按数据区域展示；当前返回页只用于列表展示，不推算全量计数。配置启用、写入受理、设备回执和独立效果仍分别呈现。

演示环境的“演示控制”位于右下角；展开后选择场景、模块来源或注入合成事件。它只存在于演示入口，生产应用不会导入这些控制。


## 统一设置、默认组织引导与平台租户（#2825）

业务入口 `/` 绑定当前宿主业务租户；平台入口 `/platform` 使用安装保留的管理租户、本地账户和独立认证。通过完整页面导航切换，平台组合不注册设备、软件、自助注册或业务 IdP 路由。租户路径只是坐标，不能将管理会话转换成目标业务会话。新租户只在正式开通回执为 enabled 且有 origin 时提供目标入口；目标宿主仍核验自己的静态绑定并要求目标账户认证。

后端配套为 rss-mdm `6ffae0dc9d19a2c5dca95c9d57fbf331e877bdba`（PR #1341）及其后继。部署必须同步替换 Web 与 `/api/v1/mdm-host/config.json`：必填 `canonicalOrigin`、业务 `tenant` 和不同的 `managementTenant`，缺失、错误 origin 或旧形状阻断启动。`rss-mdm public-host-config --config /absolute/runtime.json` 从实际安装生成 ui.json/mdm.json；不另造 platform.json、兼容解码或手填管理租户。

设置分为总览、组织与访问、设备接入、集成与运行凭据、软件与内容、系统与部署、操作记录与恢复。43 项来源清单经正式 settings/catalog 授权过滤，分别说明 owner/custody、保存/请求/实际观察版本；平台读取 tenant-administration/settings/catalog，业务读取 settings/catalog。目录返回的 API locator 只用于识别领域，界面不执行任意 href。安装已经创建首个业务租户和初始管理员，网页登录后完善资料与所选通道；引导直接复用日常材料表单。没有 claim/status HTTP 假协议，网络失败不解释为未安装。

Apple 材料支持服务端生成或导入私钥、公开 CSR 下载、证书导入、请求应用及撤销。WNS、S3、SMTP 使用各自批准 profile/身份和正式资格状态；SMTP accepted 不表示送达。Webhook 准备、确认、启用、撤销和退出沿原领域状态，秘密由部署操作员受控交付。任务签名先分发信任再激活/退出；PKI 使用三用途公开 trust、签名 CRL 与原签发 attempt 恢复。Agent 包复用 Resource/Software/Content 中已审核安装器、清单和签名资格，发布/撤回不证明真机安装。账户、IdP、Apple 组织/ADE、注册额度、Group/Scope/Policy 仍由原页面和原客户端持有。

秘密只存在于组件输入和本次请求；提交、页面离开、隐藏和会话变化时清理，不写浏览器持久存储。共享操作状态只保留绑定当前 tenant/principal/session 的原 UUID、动作、版本和非秘密比较输入；导入文件仅保留比较摘要。未知结果锁定新变更，先查原操作，404 后仍只能恢复完整原输入并显式使用同一 UUID 重试。普通资源 GET 不确认原操作；冲突先读取比较，再显式确认重新编辑。PKI 与 Agent 包没有独立原操作查询，页面保留未知状态并提示受控核对，不拿现行目录伪造回执。

平台开通使用 Idempotency-Key，精确接受 200/202；展示租户、独立管理员、宿主位置、阻塞原因及请求/观察代次。容量不足沿原开通继续，不再次创建账户。元数据替换和未使用租户删除使用 expectedRevision；后续管理员仍独立创建并要求近期认证。后端事务持有最终授权、CAS、幂等和删除准入。

系统页读取当前业务宿主 `/readyz` 的实际观察和授权 `/runtime/diagnostics`。TLS/数据库、固定安装身份/Ledger、保护钥、CA/SCEP 凭据、宿主配置、重启、备份与恢复仍由受控部署 owner 执行；页面给出实际 rss-mdm CLI 入口和原操作核对要求。当前三用途共享一个 CA 容器的联合冷备仍被后端阻断，不能通过省略用途或浏览器伪成功绕过。

正式 HTTPS 浏览器入口：`MDM_SETTINGS_BACKEND=/absolute/rss-mdm pnpm test:mdm:settings-browser`。复用后端构建租约与可丢弃 PG 环境，执行真实 Identity 登录、两范围目录、未知结果原操作查询/显式重试、独立管理员与 host_pending、第二个实际业务宿主认证和隔离，以及服务端任务密钥生成。第二宿主仅用于认证接缝，不伪造部署 enabled 回执。退出清理浏览器、产品进程、网关与环境；无原始响应、凭据或 trace 输出。外部供应方资格、受控部署应用及 Windows/macOS 真机效果须另行验收（#2826），不能从浏览器或目录状态推导。
