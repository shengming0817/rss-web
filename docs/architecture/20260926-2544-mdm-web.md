# MDM 与 Identity 独立前端

`apps/mdm` 是 Windows/macOS 企业终端管理入口，`apps/identity` 是 Identity 宿主认证入口。两者独立装配、构建和部署，不共享跨域会话。`@rss/auth` 导出既有 cookie 会话、认证 UI、OIDC flow 与路由；每个应用只创建一个 controller。`@rss/core` 持有展示基础，`@rss/api` 持有唯一 HTTP executor。原 apps/web 已由 #2514 退出，不恢复旧 bearer 页面。

## 开发

```sh
pnpm install --frozen-lockfile
pnpm dev:mdm:demo
```

打开命令输出的 loopback 地址，使用纯合成账户 `demo / demo`。顶部始终显示 Mock，可按设备、策略、安全、运营模块显式选择来源和场景，或重置并重新登录。场景包括 normal/empty/denied/forbidden/offline/unsupported/partial/conflict/unknown/late；各业务包负责其具体数据及操作分支。演示状态仅在当前开发服务内存中，重启丢弃。多标签页共用该演示状态，不代表生产会话隔离。real 来源未接入的能力返回不可用，不切回 mock。

演示使用 Vite 本地 HTTP middleware，不能构建为生产静态站点；`--mode demo` 的 build 显式拒绝。它不运行 MDM/Identity 后端，不证明设备注册、擦除、脚本效果或合规。普通 `pnpm dev:mdm` 不提供模拟 API；真实交互应使用 HTTPS 同源产品宿主。Identity 开发继续见[宿主认证 UI](20260917-2368-embedded-identity.md#交互开发)。

## 生产构建与镜像

```sh
pnpm build:identity
pnpm build:mdm
pnpm image:identity --tag rss-identity-web:VERSION
pnpm image:mdm --tag rss-mdm-web:VERSION
```

`pnpm build` 构建并扫描两个生产目录。Identity 产物不包含 MDM 路由，MDM 不包含 demo server、模拟身份或场景控制。镜像只复制对应应用的 dist，使用独立版本标签。构建使用当前工作树，允许未提交修改。类型/组件/API 验证采用现有 `pnpm typecheck/lint/format:check/test:coverage/test:boundary`，不需要源码快照、提交摘要或 consumer receipt。

两个应用分别拥有独立域名上的 `/`；不能在同一根路径同时部署两个 app。Nginx 配置与 TLS 材料由宿主注入 `/run/config`，前端镜像不持有秘密。

MDM 宿主需提供既有 Identity config/context 和嵌入 Identity HTTP v2，以及新增的静态 `/api/mdm-host/v1/config.json`：

```json
{"canonicalOrigin":"https://mdm.example.test","tenant":"11111111-1111-4111-8111-111111111111"}
```

origin 必须严格匹配 HTTPS 页面 origin，tenant 是宿主指定资源定位符；不生成租户 header，也不授予权限。示例 [`deploy/mdm/gateway.conf.example`](../../deploy/mdm/gateway.conf.example) 精确区分 config、Identity callback、业务 API 和 SPA。这是前端接入要求；rss-mdm 宿主新增配置、路由和实际生产部署仍待后端 owner 接入，不宣称已交付。

升级时记录两个现用前端镜像标签/ID，分别构建目标产品镜像，保留宿主配置、TLS 和后端数据卷，仅替换对应 gateway 镜像；验证 `/`、后端 `/livez`/`/readyz`、登录/退出、受控工作区与 API 错误；readiness 未通过不切流。失败时将该 gateway 恢复到先前镜像并重建容器，不回滚 Identity/MDM 数据库、不重放未知写操作。两个前端可以独立升级回滚；若后端合同发生破坏性变化，先按后端部署说明协调版本，不靠旧 wire fallback。

MDM `v1/v2/v3` 路径不自动改写：v1 路径段为 `authorization`、`devices`（含 collection-runs）和 `software-sources`；v2 为 `asset-fields`、`device-queries`、`devices`（含 inventory/operations）、`saved-queries`、`groups`、`scopes`、`policies`、`tasks`；v3 为 `resources`、`enrollments`、`devices`（含 registrations）。Identity transport 不扩大 allowlist。MDM transport 复用同一 executor，精确预期 200/201/202/204，闭合解码 Identity 认证错误与 MDM 产品错误。响应 request-id/Retry-After 目前未暴露给页面，不宣称已消费这些元数据。

缺失能力使用明确的 `/api/mdm-candidate/v1/` 候选命名空间，**不是已发布的后端 API**。后端 owner 为 rss-mdm；后续真实合同落地时调整 domain adapter 和交互。基础候选：

| 请求 | 响应/语义 | 权限、失败、版本 |
|---|---|---|
| `GET /api/mdm-candidate/v1/workspace` | `{modules:[{id,source,available}]}`；id 为 devices/policies/security/operations，source 为 real/mock，available 为 true/false/null | 有效会话；后端决定每资源权限；无分页/写入；null 为导航未知。生产拒绝 mock source。401 清会话，403 拒绝，503 不可用；不自动重试 |

业务 DTO 必须经 decoder。读响应绑定当前会话，失效或旋转后的迟到响应不再呈现。业务 403/409/503 与协议错误不清除有效认证；401 才通知 session owner。业务并发派发与凭据轮换由同一 owner 双向协调，写入在派发时取得当前 CSRF，不全局重试；Identity no-replay 与 MDM 每操作精确幂等合同分别处理，未知结果需要显式核实。

新增 feature 在 `apps/mdm/src/features.ts` 注册普通路由和入口，业务模块不再装配 session/transport。导航提示不代表授权；真实页面请求仍由服务端复核。候选请求/响应、分页/CAS/批准状态及异常覆盖随对应业务项维护，不能把未实现服务标成已接入。

共享包的 UI 与纯会话入口见 [`@rss/auth`](../../packages/auth/README.md)。网关须直接面对客户端，并由后端将该网关 peer 配置为可信来源；示例覆盖客户端转发头，仅转发实际 peer 地址，并沿用 rss-mdm 的登录/API 限流、连接数、16 KiB 正文及 10 秒客户端读取预算；429 返回安全错误码与 Retry-After，前端不自动重放写入。诊断日志只含关联 ID、状态和时延，不含 URL、header 或 body。

## 设备控制台

从工作区进入设备目录，可查看包含首次 pending 注册的授权设备投影；资产搜索另用已发布的异步查询，不在浏览器合并资产和注册列表来推断完整授权集合。平台尚未采集时显示未知。目录统计、详情、注册与批量预览由同一个 HTTP demo 状态持有，重置同时清除查询、组任务、幂等回执和分页。

搜索提交返回任务 ID，使用“读取任务状态”显式刷新；完成后读取结果和 facets。查询与组结果分页只根据服务端 nextCursor 结束，允许空尾页；不按返回行数推断完成。字段状态 known/null/missing/unsupported/deleted/conflict、来源和 lastKnown 分别呈现，时间不产生资产 TTL。asset_states 聚合计算字段数，不代表设备数。离开页面只忽略迟到响应，不取消服务端任务。

Manual、个人查询、组定义及归属编辑使用当前 revision；冲突保留草稿，重读服务器值后由操作者比较并再次提交。未知写入不自动重试；明确重放复用原 operationId 和完整正文。组条件先保存，再预览已保存版本；只有重算发布成员，预览不修改成员集，规则解释由服务端提供。

注册通过 Web Crypto 生成 256-bit Base64URL 口令，操作者确认安全交付后提交；表单立即清除口令，页面不持久化口令或完整秘密请求。未知结果保留非秘密操作身份；精确重放必须重新输入原口令。create/resume/cancel 使用 Idempotency-Key、HTTP 200；撤销凭据的已发布 wire 回执是 `operation_id`/`registration`，与 enrollment 的 camelCase 不混用。授权期限是注册凭据的期限，不是资产期限。设备侧 profile 安装、APNs、Agent 安装 ACK 与有效注册/通道就绪不同；本前端不代替设备协议下载、TokenUpdate 或采集验收。

ADE、Windows 自动化开通、入职、重新分配、丢失、退役、擦除及双通道引导均提供候选批量预览。冻结目标的设备版本、registration 和 generation，提交时重新复核；无权限、平台不支持、离线、旧世代、版本冲突逐设备列出。受理、下发、设备回执、实际效果和合规分别显示；demo 只受理模拟请求，效果与合规保持未知。详细执行记录由 #2546 配置与执行模块承接。

### devices-v1 候选合同

下表统一前缀 `/api/mdm-candidate/v1`，后端 owner **rss-mdm**。这些接口尚未由后端发布。响应都包含 `{contract:"devices-v1",tenantId,source:"real"|"mock"}`；客户端校验租户、目标与闭合字段，生产拒绝 mock。完整 DTO 由 `features/devices/clients/directory.ts` 定义，未来真实合同落地时直接替换该适配器，不保留旧 DTO fallback。

| 请求 | 输入 / 响应核心 | 授权与一致性 |
|---|---|---|
| `GET /devices?limit&cursor` | `{snapshot,items:[{id,name,platform,status,inventoryAvailable,revision,channels,owner,department}],nextCursor,statistics:{total,pending,windows,macos,withInventory}}` | 服务端授权目录；含无资产 pending，platform 可 unknown；冻结列表和统计，limit 1..1000，不透明 cursor 绑定投影 |
| `GET /devices/{id}` | `{device,readiness,capabilities:[{action,channel,support}],enrollments:[uuid]}` | 目标可见性由后端决定；readiness 为 unknown/pending_token/ready/offline；提示不是授权 |
| `GET /devices/{id}/hardware` | `{device,snapshot,items:[ResolvedField],nextCursor}` | 设备 inventory_read；沿用字段状态/来源/lastKnown 结构，硬件键属于此候选投影 |
| `GET /devices/{id}/software` | `{device,snapshot,state,items:[{id,name,version:ResolvedField}],nextCursor}` | 设备 inventory_read；state known/missing/unsupported/partial；空清单不等于未采集 |
| `GET /devices/{id}/history` | `{device,snapshot,items:[{id,at,event,operation}],nextCursor}` | 设备历史读取；event 闭合集，游标冻结时间与事件身份，不输出秘密 |
| `PUT /devices/{id}/assignment` | `Operation<{owner:string|null,department:string|null}>` → 当前 detail | 设备归属写权限；独立设备 revision CAS，不写成 Manual 资产字段 |
| `GET /groups?limit&cursor` | `{snapshot,items:[GroupSummary],nextCursor}` | 设备 group_read 与全租户 inventory_read；不是用户授权组列表 |
| `POST /devices/batch-previews` | `Operation<{action,devices:[id]}>` → HTTP 200 batch | 逐目标核实可见性、动作、平台/通道与世代；expectedRevision=0；id=operationId |
| `GET /devices/batch-previews/{id}` | 当前 batch | 同一租户/操作者可见的原预览或执行状态 |
| `POST /devices/batch-previews/{id}/execute` | `Operation<{confirmed:true}>` → HTTP 202 batch | 预览 revision CAS；重新授权并复核冻结版本/世代，不静默替换目标；逐目标受理不代表设备效果 |
| `POST /devices/batch-previews/{id}/cancel` | `Operation<{}>` → HTTP 200 batch | 只取消尚未执行的预览，不能取消或回滚已下发动作 |

`Operation<T>` 为 `{operationId,expectedRevision,input:T}`。batch 为 `{id,revision,action,phase,targets}`；phase 为 preview/accepted/cancelled；target 为 `{device,deviceRevision,registration,generation,blocked,execution,dispatch,receipt,effect,compliance}`。未知/不可见目标可没有版本或注册；blocked 为 null 或 stale_generation/offline/permission_denied/unsupported/not_registered/conflict。执行引用只有已受理目标才有。

候选权限名最终由 rss-mdm 定义；浏览器不授予权限或计算权威成员。候选错误沿用 MDM 闭合语义：400 malformed_request、401 invalid_identity、403 permission_denied、404 management_device_not_found/operation_not_found、409 operation_conflict、429 request_limited、501 action_not_supported、503 service_unavailable/operation_unknown。401 交给会话 owner；其余不清有效会话，不自动重试。模拟模式提供空、拒绝、离线、不支持、逐设备部分阻塞、冲突、未知提交和迟到响应；真实失败不进入模拟 handler。

## 配置、持续分配与执行控制台

策略模块提供 Scope、资源/内容上传、平台配置目录、持续分配、脚本入口、多步工作流、执行中心与显式工作流审批。普通脚本在资源库编辑参数和输出 Schema，再引用资源版本创建持续分配；没有独立 ScriptPlan 或普通脚本第二主体审批。策略页一次 CAS 保存来源、版本、动态 Scope、触发/频率、启停、退出行为和可选 UTC 有效窗口。Scope 成员为空时可以保存；可选预览不保存策略或创建运行。

后台成员计算序号与配置 revision 独立。“刷新进度”保留编辑草稿，“重新载入配置”明确替换草稿；409 后先比较最新配置再提交。未知写入只能显式重放原 operationId 与完整请求；Unknown 执行效果不会自动重发。取消在途运行不代表撤销已生效配置，取消请求/确认、受理/派发/回执/执行/效果/合规分别展示。既有执行记录保留，资源换版或设备身份变化不改写旧结果。

DemoControls 可注入 UTC 时间、设备注册或签到事件；事件只推进 HTTP demo 服务端，页面不持有调度器。设备/组变更后的动态 Scope 在下一次模拟事件解析。真实模式不启动该 owner，也不在真实失败后降级。演示重置会清除全部策略、运行、工作流、上传与分页状态；它不证明生产重启持久化恢复。

| 能力 | 交互/Mock | 真实接入 | 产品验收 |
|---|---|---|---|
| Scope、资源/上传、原生操作读写 | 已实现 | 当前 v2/v3 adapter；尚未运行真实 MDM 联调 | 待宿主/设备验证 |
| 平台配置目录、差异/预检、持续分配 | 已实现 candidate mock | 等待 rss-mdm 最终合同（#2567–#2569） | 未证明真实设备效果 |
| 多步查询/脚本/条件/维护窗口/显式人工审批 | 已实现 candidate mock | 候选，不宣称后端已支持 | 待产品验收 |
| 执行汇总、诊断、批次/设备链接 | 已实现 candidate mock | native adapter 与候选投影分开 | 受理不等于效果/合规 |

#2570 本轮纳入持续分配前端差异与 mock；真实 API 联调、新设备入组/退组重入/重启恢复等跨仓验收仍待其后端前置就绪，不能以本轮 mock 关闭 #2570。

### policies-v1 候选合同

统一前缀 `/api/mdm-candidate/v1`，后端 owner **rss-mdm**。响应以 `{contract:"policies-v1",tenantId,source}` 包装，生产拒绝 mock；没有旧 Plan wire 兼容层。租户会话和最终每资源授权由服务端持有。`Operation<T>` 沿用 operationId/expectedRevision/input；写成功回执支持同主体、同路径、同正文精确重放，内容改变返回 409。

| 请求 | 核心语义 |
|---|---|
| `GET /policies/{scopes,resources,policies,workflows,approvals}?limit&cursor` | 冻结 catalog 页 `{snapshot,items,nextCursor}`；审批只列显式 workflow step，非机器 Start permit |
| `GET/POST /policies/assignments/{id}` | 读 `{policy}`；写 `Operation<{action:"put",definition}>` 或 archive/cancel_run。definition 为 source(resource/configuration)、resource、resourceVersion、parameters、scope、enabled、exitBehavior(cancel/retain)、trigger(on_change/interval/check_in)、validity(null或start/end)。policy 包含独立 revision、computation(sequence/status/at)、逐设备 members(reason/execution) |
| `POST /policies/assignments/{id}/preview` | `{definition}` → `{members}`，无执行副作用，不是保存前置 |
| `GET/POST /policies/configurations/{id}` | 配置 name/platform/format/versions/settings；create/version/publish/archive 使用 CAS；读取 diff，异步预检只产出适用性/冲突/漂移提示 |
| `GET/POST /policies/workflows/{id}` | 条件、步骤、失败分支、Schema/字段绑定、schedule；run 使用冻结引用，显式人工审批、取消与结果读取；未知不盲重试 |
| `GET /executions?batch&limit&cursor`、`GET /executions/{id}` | 统一原生/策略/工作流/设备批量 origin；受理、派发、回执、执行、效果、合规、attempt、nativeCode、waitingReason 分别解码；策略额外保留配置 revision、取消状态与纯合成输出 |

错误沿用闭合 MDM 语义：400 无效定义、401 会话无效、403 无权限、404 引用不存在、409 CAS/幂等冲突、501 不支持、503 不可用或未知提交。无全局写重试。动态 Scope 与资源版本失效逐设备阻塞；缺失 Scope 显示计算阻塞，不能当作完整空结果或全部失败。资源/配置版本被策略或工作流引用时不允许归档。
