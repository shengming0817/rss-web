# WEB-PR-008 Identity UX receipt

## Dependency and source

- Depends on WEB-PR-006 / PR #19 for the deployment-fixed, same-origin tenant Edge.
- Depends on WEB-PR-007 / PR #20 for the memory-only session, verified profile authority,
  refresh single-flight, retry-once, and atomic local invalidation.
- RSS is a read-only contract and permission reference. This change modifies only `rss-web`.
- Login, profile, logout, and logout-all continue to use the reviewed contract baseline in
  `docs/contracts/20260809-current-rss-baseline.md`; no schema copy or runtime registry exists.

## Delivered boundary

- The Web composition root creates exactly one same-origin HTTP transport and Identity session.
- Anonymous startup and reload route to `/login` without a profile/bootstrap request.
- The login form accepts only username and password. Tenant is never browser-selectable and is
  injected by the Edge only for login and refresh.
- The shell is reachable only from `authenticated` or `refreshing` state backed by a branded
  `VerifiedProfile`; a login 201 response alone never establishes authority. Protected navigation
  rechecks authority after asynchronous route resolution and before commit.
- Logout clears local authority before remote confirmation. Logout-all uses an accessible
  destructive confirmation and has the same fail-closed local behavior. The application blocks a
  new login until the outstanding remote sign-out settles, so stale completion cannot revoke a new
  session.
- `@rss/identity` remains framework-neutral; Vue composition and messages live in `apps/web`.

## Security and tenant review

- Password is removed from the input immediately after submission. Passwords and tokens are not
  stored, logged, rendered in notices, placed in query strings, or copied into Pinia.
- UI error mapping is closed over safe status/cause/session coordinates and never renders backend
  message, details, request body, token, or request ID.
- Profile subject/tenant/kind are displayed only after session verification. They are not used to
  author tenant headers or infer permissions.
- The app does not import `@rss/api/session`, parse JWTs, add a second refresh path, or add client
  tenant resolution. Static guards and reverse ESLint fixtures enforce these constraints.
- Required RSS deployment permissions for usable profile authority remain
  `identity:profile:read`, `identity:profile:field:subject`, and
  `identity:profile:field:tenant_id`; redacted authority fails closed.
